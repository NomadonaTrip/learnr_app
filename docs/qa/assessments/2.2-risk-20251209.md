## High Risks (Score 6)

### 1. SEC-001: OpenAI API Key Exposure in Logs/Errors

**Score: 6 (High)**

**Probability**: Medium - The script logs extensively including API errors. While the settings pattern is used, exception messages from OpenAI SDK may contain key fragments.

**Impact**: High - API key exposure would allow unauthorized usage, cost accumulation, and potential data access.

**Affected Components**:
- `scripts/extract_babok_concepts.py:349-352` (exception handling)
- `src/config/settings.py` (API key storage)

**Mitigation**:
- Audit all exception handlers to ensure API keys are never logged
- Use environment variable `OPENAI_API_KEY` (already implemented via settings)
- Add log sanitization for any API-related errors
- Consider using OpenAI organization-level key restrictions

**Testing Focus**:
- Review log output in verbose mode for sensitive data
- Test error paths with invalid API keys

---

### 2. DATA-001: PDF Parsing Misses Sections (Data Loss)

**Score: 6 (High)**

**Probability**: Medium - BABOK PDF structure is complex with multi-page sections, tables, and figures. The regex-based parser (`^(\d+(?:\.\d+)*)\s+(.+)$`) may miss edge cases.

**Impact**: High - Missing sections means missing concepts, affecting BKT model completeness and certification prep accuracy.

**Affected Components**:
- `scripts/extract_babok_concepts.py:124` (SECTION_PATTERN regex)
- `scripts/extract_babok_concepts.py:140-202` (parse_babok_pdf method)

**Mitigation**:
- Add section coverage validation (already implemented at 95% threshold)
- Log all skipped pages/sections for manual review
- Consider alternative PDF parsers (pdfplumber) for comparison
- SME review checkpoint catches gaps before database insert

**Testing Focus**:
- Verify section count matches expected BABOK structure (~200-300 sections)
- Test with sample PDF excerpts containing edge cases

## Medium Risks (Score 4)

### 3. TECH-001: GPT-4 Rate Limiting Halts Extraction

**Score: 4 (Medium)**

**Probability**: Medium - Processing 200+ sections with chunked content could hit OpenAI rate limits.

**Impact**: Medium - Extraction fails mid-process requiring restart.

**Mitigation**:
- Exponential backoff implemented (`scripts/extract_babok_concepts.py:354-355`)
- Consider adding checkpoint/resume capability
- Log token usage for capacity planning

---

### 4. TECH-002: JSON Parsing Fails on Malformed LLM Response

**Score: 4 (Medium)**

**Probability**: Medium - GPT-4 may occasionally produce invalid JSON despite prompt instructions.

**Impact**: Medium - Section concepts lost, requires manual intervention.

**Mitigation**:
- JSON mode enabled in API call (`response_format={"type": "json_object"}`)
- Retry logic with 3 attempts implemented
- Graceful handling of both array and wrapped responses

---

### 5. DATA-002: Deduplication Too Aggressive (Data Loss)

**Score: 4 (Medium)**

**Probability**: Medium - 85% similarity threshold may merge semantically distinct concepts.

**Impact**: Medium - Loss of concept granularity affects BKT precision.

**Mitigation**:
- Threshold is configurable via `ConceptDeduplicator` constructor
- Deduplication logs all merges for review
- CSV export allows SME verification before DB commit

---

### 6. OPS-001: No Idempotency - Re-runs Create Duplicates

**Score: 4 (Medium)**

**Probability**: Medium - Script does not check for existing concepts before insert.

**Impact**: Medium - Database pollution requires manual cleanup.

**Mitigation**:
- Add `--clear-existing` flag to delete course concepts before insert
- Or implement upsert logic based on (course_id, name) uniqueness
- `delete_all_for_course` method exists in repository

---

### 7. OPS-002: Missing Monitoring for Extraction Pipeline

**Score: 4 (Medium)**

**Probability**: Medium - Long-running extraction (potentially hours) has no health checks.

**Impact**: Medium - Silent failures go undetected.

**Mitigation**:
- Token usage and API call logging implemented
- Add structured logging with JSON format
- Consider progress persistence for large extractions

---

## Conclusion

Story 2.2 presents **moderate risk** (64/100 score) primarily due to external dependencies (OpenAI API, PDF parsing) and lack of idempotency. The implementation includes reasonable mitigations:

**Strengths:**
- Comprehensive validation with AC thresholds
- SME review checkpoint before database commit
- Retry logic with exponential backoff
- Course-scoped architecture for multi-course support

**Gaps:**
- No idempotency for re-extraction scenarios
- Log sanitization needs audit for API keys
- No resume capability for long extractions

**Recommendation:** CONCERNS - Address SEC-001 (log audit) and OPS-001 (idempotency) before production use.
