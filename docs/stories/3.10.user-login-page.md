# Story 3.10: User Login Page

## Status

Ready for Review

---

## Story

**As a** returning user,
**I want** to log in to my account from the login page,
**so that** I can access my personalized learning dashboard and continue my progress.

---

## Acceptance Criteria

1. `/login` route displays a functional login form (replacing the "Coming soon" placeholder)
2. Fields: Email (required), Password (required)
3. Email validation: valid format
4. Password field: required, no client-side strength requirements (backend validates)
5. Submit calls `POST /v1/auth/login` via authService
6. On success: Store JWT token, set auth state, redirect to `/diagnostic`
7. On 401 error: Display "Invalid email or password" inline
8. On 429 error: Display "Too many attempts. Please try again in X minutes" with retry countdown
9. On 500 error: Display generic toast "Unable to log in. Please try again."
10. "Forgot password?" link navigates to `/forgot-password` (placeholder acceptable)
11. "Create account" link navigates to `/onboarding`
12. Form is keyboard accessible and screen reader compatible
13. Design consistent with Account Creation page (glassmorphism, typography, spacing)

## Dev Notes

### Story Context & Epic Placement

**Gap Analysis:** This story fills a gap between Epic 1 (backend authentication) and Epic 3 (frontend user flows):
- **Epic 1, Story 1.4** implemented the backend `POST /v1/auth/login` API
- **Epic 3, Story 3.1** references "I already have an account" → `/login` navigation (AC8)
- **No story** existed for the frontend login page implementation

This story completes the authentication user journey by providing the frontend counterpart to the backend login API. It is placed in Epic 3 as it is a frontend user flow component.

---

### Redirect Behavior Note

**AC6 Redirect Target:** Login success redirects to `/diagnostic` for MVP.

**Rationale:** New users go through onboarding → account creation → diagnostic. Returning users logging in are directed to `/diagnostic` to continue or review their assessment.

**Future Enhancement (not in scope):** A future story could add conditional redirect logic:
- If diagnostic completed → redirect to `/dashboard`
- If diagnostic in progress → redirect to `/diagnostic` (resume)
- If no diagnostic started → redirect to `/diagnostic` (start)

For MVP, always redirecting to `/diagnostic` is acceptable as the diagnostic page can handle showing results or resuming.

### LoginPage Component Structure

```typescript
// pages/LoginPage.tsx
import { useForm } from 'react-hook-form'
import { zodResolver } from '@hookform/resolvers/zod'
import { useNavigate } from 'react-router-dom'
import { useState } from 'react'
import axios from 'axios'
import toast from 'react-hot-toast'

import { loginSchema, type LoginFormData } from '@/utils/loginValidation'
import { authService } from '@/services/authService'
import { useAuthStore } from '@/stores/authStore'

export function LoginPage() {
  const navigate = useNavigate()
  const { login } = useAuthStore()
  const [rateLimitSeconds, setRateLimitSeconds] = useState<number | null>(null)

  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
    setError,
  } = useForm<LoginFormData>({
    resolver: zodResolver(loginSchema),
    mode: 'onBlur',
  })

  const onSubmit = async (data: LoginFormData) => {
    try {
      const response = await authService.login({
        email: data.email,
        password: data.password,
      })

      // Success: store auth state and redirect
      login(response.user, response.token)
      toast.success('Welcome back!')
      navigate('/diagnostic')

    } catch (error) {
      if (axios.isAxiosError(error)) {
        const status = error.response?.status
        const details = error.response?.data?.error?.details

        if (status === 401) {
          setError('root', {
            type: 'manual',
            message: 'Invalid email or password',
          })
        } else if (status === 429) {
          const retryAfter = details?.retry_after_seconds || 900
          setRateLimitSeconds(retryAfter)
          // Start countdown timer
        } else {
          toast.error('Unable to log in. Please try again.')
        }
      } else {
        toast.error('Network error. Check your connection.')
      }
    }
  }

  return (
    // Component JSX
  )
}
```

### Rate Limit Countdown Hook

```typescript
// hooks/useCountdown.ts
import { useState, useEffect, useCallback } from 'react'

export function useCountdown(initialSeconds: number | null, onComplete?: () => void) {
  const [seconds, setSeconds] = useState<number | null>(initialSeconds)

  useEffect(() => {
    if (seconds === null || seconds <= 0) {
      if (seconds === 0 && onComplete) {
        onComplete()
      }
      return
    }

    const timer = setInterval(() => {
      setSeconds((prev) => (prev !== null && prev > 0 ? prev - 1 : null))
    }, 1000)

    return () => clearInterval(timer)
  }, [seconds, onComplete])

  const start = useCallback((newSeconds: number) => {
    setSeconds(newSeconds)
  }, [])

  const reset = useCallback(() => {
    setSeconds(null)
  }, [])

  return { seconds, start, reset, isActive: seconds !== null && seconds > 0 }
}

// Format seconds as "X minutes Y seconds"
export function formatCountdown(seconds: number): string {
  const mins = Math.floor(seconds / 60)
  const secs = seconds % 60
  if (mins > 0) {
    return `${mins} minute${mins !== 1 ? 's' : ''} ${secs} second${secs !== 1 ? 's' : ''}`
  }
  return `${secs} second${secs !== 1 ? 's' : ''}`
}
```

- Error messages: Linked via `aria-describedby`
- Required fields: Marked with `aria-required="true"`
- Invalid state: `aria-invalid="true"` when field has error
- Loading state: Submit button shows spinner with `aria-busy="true"`
- Focus: Auto-focus email field on mount

**Example:**
