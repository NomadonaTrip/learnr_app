# Story 5.12: Clear Completed Reading Materials

## Status

**Ready for Review**

## Story

**As a** learner,
**I want to** remove completed reading materials from my library,
**so that** my reading queue stays focused on areas where I still need improvement.

## Acceptance Criteria

1. "Clear All Completed" button visible on Reading Library page when viewing Completed tab AND completed items exist
2. Clicking "Clear All Completed" opens a confirmation modal with item count and reassurance message
3. Confirming the modal clears all completed items via existing `POST /api/v1/reading/queue/batch-dismiss` endpoint
4. Success toast displays "Cleared X items from your library" after batch clear
5. Kebab menu (three dots) appears on each completed reading card in top-right corner
6. Kebab menu contains "Remove from library" option with trash icon
7. Single item removal is immediate (optimistic update) with undo toast
8. Undo toast displays for 5 seconds with "Undo" action button
9. Clicking "Undo" within 5 seconds restores the item to completed status
10. Cleared items use status `dismissed` (reusing existing status, no schema change)
11. All UI components follow existing design system (Tailwind CSS, Headless UI, 14px card radius)
12. Keyboard navigation: Tab through controls, Enter to activate, Escape to close modal
13. Screen reader: Announce item count in modal, announce "Item removed" on clear
14. Loading states: Button shows spinner during batch clear, modal confirm button disabled during API call
15. Error handling: Show error toast on failure, restore items on single-item failure
16. Unit tests: All new components tested
17. Integration tests: Batch clear flow and single item removal with undo

### API Specifications

**IMPORTANT: Reuse Existing Endpoint**

This story leverages the existing `batch-dismiss` endpoint rather than creating a new one.

**POST `/api/v1/reading/queue/batch-dismiss`** (EXISTING)

Already implemented in `apps/api/src/routes/reading.py:704-754`. Clears multiple reading queue items by setting status to `dismissed`.

**Request Schema (existing):**

```json
{
  "queue_ids": ["uuid1", "uuid2", "uuid3"]
}
```

**Response Schema (existing):**

```json
{
  "dismissed_count": 12,
  "remaining_unread_count": 5
}
```

**Note:** Response returns `remaining_unread_count` not `remaining_completed_count`. Frontend should handle this accordingly.

**PUT `/api/v1/reading/queue/{queue_id}/status`** (EXISTING)

Already implemented for single-item status updates. Use for single-item removal and undo.

**Request Schema:**

```json
{
  "status": "dismissed"
}
```

**For Undo (restore to completed):**

```json
{
  "status": "completed"
}
```

### State Management

**Optimistic Update Pattern for Single Item Removal:**

```typescript
const removeItemMutation = useMutation({
  mutationFn: (queueId: string) => updateItemStatus(queueId, "dismissed"),
  onMutate: async (queueId) => {
    await queryClient.cancelQueries(["reading-queue"]);
    const previousData = queryClient.getQueryData(["reading-queue", filters]);

    // Optimistically remove from cache
    queryClient.setQueryData(["reading-queue", filters], (old) => ({
      ...old,
      items: old.items.filter((item) => item.queue_id !== queueId),
    }));

    return { previousData };
  },
  onError: (err, queueId, context) => {
    // Rollback on error
    queryClient.setQueryData(["reading-queue", filters], context.previousData);
    showErrorToast("Failed to remove item");
  },
  onSuccess: () => {
    showUndoToast();
  },
});
```

**React Query Invalidation:**

- On batch clear success: Invalidate `['reading-queue', { status: 'completed' }]`
- On single item remove/restore: Invalidate `['reading-queue']`
