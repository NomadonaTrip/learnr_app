## Story

**As a** system,

**so that** the knowledge profile reflects the latest evidence.

## Acceptance Criteria

1. Belief update service `/apps/api/src/services/belief_updater.py`
2. **Core Bayesian Update:**

   ```python
   def update_beliefs(user_id, question, is_correct, beliefs):
       """
       Update beliefs for all concepts tested by this question.

       Uses Beta-Bernoulli model with slip/guess parameters.
       """
       updates = {}

       for concept_id in question.concept_ids:
           belief = beliefs[concept_id]

           # BKT update equations
           p_mastered = belief.alpha / (belief.alpha + belief.beta)
           slip = question.slip_rate
           guess = question.guess_rate

           if is_correct:
               p_correct = (1 - slip) * p_mastered + guess * (1 - p_mastered)
               posterior = (1 - slip) * p_mastered / p_correct
           else:
               p_incorrect = slip * p_mastered + (1 - guess) * (1 - p_mastered)
               posterior = slip * p_mastered / p_incorrect

           # Update Beta parameters
           new_alpha = belief.alpha + posterior
           new_beta = belief.beta + (1 - posterior)

           updates[concept_id] = BeliefState(
               alpha=new_alpha,
               beta=new_beta,
               response_count=belief.response_count + 1
           )

       return updates
   ```

3. **Prerequisite Propagation** (weaker signal):
   - If correct: Slightly increase belief for prerequisite concepts
   - Propagation weight: 0.2-0.3 (configurable)
4. Persist updates atomically
5. Calculate actual information gain (for analytics):
   ```python
   actual_info_gain = entropy_before - entropy_after
   ```
6. Store belief snapshot in response record (for debugging/analysis)
7. Logging: "Updated {N} concepts for user {id}, info gain: {value}"
8. Performance: Update completes in <50ms
9. **Unit tests:**
   - Correct answer increases mastery probability
   - Incorrect answer decreases mastery probability
   - Slip/guess parameters affect update magnitude
   - Multi-concept questions update all concepts
10. Integration test: Sequential answers update beliefs progressively

### BKT Mathematical Formulas [Source: architecture/bkt-architecture.md#mathematical-primer]

**Bayesian Update Equations:**

```python
# Prior probability of mastery
p_mastered = alpha / (alpha + beta)

# On CORRECT answer:
p_correct = (1 - slip) * p_mastered + guess * (1 - p_mastered)
posterior_mastered = (1 - slip) * p_mastered / p_correct

# On INCORRECT answer:
p_incorrect = slip * p_mastered + (1 - guess) * (1 - p_mastered)
posterior_mastered = slip * p_mastered / p_incorrect

# Update Beta parameters:
new_alpha = alpha + posterior_mastered
new_beta = beta + (1 - posterior_mastered)
```

**Beta Distribution Entropy:**

```python
from scipy.special import betaln, digamma

def beta_entropy(alpha: float, beta: float) -> float:
    """Calculate entropy of Beta(alpha, beta) distribution."""
    return (
        betaln(alpha, beta)
        - (alpha - 1) * digamma(alpha)
        - (beta - 1) * digamma(beta)
        + (alpha + beta - 2) * digamma(alpha + beta)
    )
```

**Information Gain:**

```python
info_gain = entropy_before - entropy_after
```

### Worked Numerical Example

**Scenario:** User answers a question correctly for a concept with uninformative prior.

**Before:**

- `alpha = 1.0, beta = 1.0` (uninformative prior)
- `mean = 1.0 / 2.0 = 0.50` (50% mastery probability)
- `slip = 0.10, guess = 0.25`

**Calculation (correct answer):**

```python
p_mastered = 1.0 / 2.0 = 0.50
p_correct = (1 - 0.10) * 0.50 + 0.25 * (1 - 0.50)
          = 0.90 * 0.50 + 0.25 * 0.50
          = 0.45 + 0.125 = 0.575

posterior = (1 - 0.10) * 0.50 / 0.575
          = 0.45 / 0.575 = 0.7826

new_alpha = 1.0 + 0.7826 = 1.7826
new_beta = 1.0 + (1 - 0.7826) = 1.2174
```

**After:**

- `alpha = 1.783, beta = 1.217`
- `mean = 1.783 / 3.0 = 0.594` (59.4% mastery - increased from 50%)
- `confidence = 3.0 / 5.0 = 0.60` (60% confidence)

### Edge Cases and Safety

**Division Safety:**

- When `p_correct` or `p_incorrect` approaches 0, use `max(value, 1e-10)` to prevent division by zero
- This can occur with extreme slip/guess values (edge case: slip=0, guess=0)

**Parameter Bounds:**

- Alpha and beta must remain > 0 (enforced by DB CHECK constraints)
- The Bayesian update naturally maintains this as long as inputs are valid

**Very Large Alpha/Beta:**

- As alpha + beta grows large, updates become smaller (high confidence = slow to change)
- This is expected behavior - confident beliefs require more evidence to shift
- No special handling needed; the math naturally handles this

**Concurrency:**

- `BeliefRepository.bulk_update()` uses row-level locking via SQLAlchemy
- Concurrent quiz sessions for the same user will serialize at the DB level
- No application-level locking required
