# Story 5.11: Concept-Linked Reading Intervention

## Status

**Draft** - Pending Review

## Story

**As a** system,
**I want to** track reading completion per concept and notify users who repeatedly fail without studying,
**so that** stuck students are guided to use the reading materials that will help them get unstuck.

## Context

This story closes the loop on the stuck-student intervention mechanism. Epic 5 (Stories 5.5-5.9) establishes the asynchronous reading queue that surfaces semantically-matched BABOK chunks when users fail questions. However, the current specification lacks:

1. **Concept linkage** - Reading items don't explicitly track which concepts they address
2. **Failure detection** - No tracking of consecutive failures per concept
3. **Intervention escalation** - No notification when users repeatedly fail without completing recommended reading

This story creates a closed-loop intervention system:
- BKT/IRT signals failure on concept → reading chunks surfaced (existing)
- System tracks consecutive failures per concept (NEW)
- System checks if user has unread materials for struggling concepts (NEW)
- After threshold failures, system nudges user to complete reading (NEW)

### AC2: Consecutive Failure Tracking

1. Extend `belief_states` table to track failure streaks:
   ```sql
   ALTER TABLE belief_states ADD COLUMN consecutive_failures INT NOT NULL DEFAULT 0;
   ALTER TABLE belief_states ADD COLUMN failures_since_reading INT NOT NULL DEFAULT 0;
   ALTER TABLE belief_states ADD COLUMN last_failure_at TIMESTAMP;
   ALTER TABLE belief_states ADD COLUMN last_reading_completed_at TIMESTAMP;
   ```

2. Update failure tracking on each quiz response:
   ```python
   def update_failure_tracking(belief_state: BeliefState, is_correct: bool) -> BeliefState:
       if is_correct:
           # Reset consecutive failures on correct answer
           belief_state.consecutive_failures = 0
           # Note: failures_since_reading only resets when reading is completed
       else:
           # Increment failure counters
           belief_state.consecutive_failures += 1
           belief_state.failures_since_reading += 1
           belief_state.last_failure_at = datetime.utcnow()

       return belief_state
   ```

3. Reset `failures_since_reading` when user completes reading for the concept:
   ```python
   def on_reading_completed(user_id: UUID, reading_item: ReadingQueueItem):
       for concept_id in reading_item.concept_ids:
           belief_state = get_belief_state(user_id, concept_id)
           if belief_state:
               belief_state.failures_since_reading = 0
               belief_state.last_reading_completed_at = datetime.utcnow()
               db.commit()
   ```

### AC3: Unread Materials Check

1. Service method to check for unread materials:
   ```python
   def has_unread_materials_for_concept(user_id: UUID, concept_id: UUID) -> bool:
       """Check if user has unread reading queue items addressing this concept."""
       count = db.query(ReadingQueue).filter(
           ReadingQueue.user_id == user_id,
           ReadingQueue.status == 'unread',
           concept_id == any_(ReadingQueue.concept_ids)
       ).count()
       return count > 0

   def get_unread_count_for_concept(user_id: UUID, concept_id: UUID) -> int:
       """Get count of unread items for a concept."""
       return db.query(ReadingQueue).filter(
           ReadingQueue.user_id == user_id,
           ReadingQueue.status == 'unread',
           concept_id == any_(ReadingQueue.concept_ids)
       ).count()
   ```

### AC5: Gentle Nudge Notification (Threshold = 3)

1. After 3rd consecutive failure on a concept with unread materials, include nudge in answer response:
   ```python
   def check_intervention_needed(user_id: UUID, concept_id: UUID) -> Optional[InterventionNudge]:
       belief_state = get_belief_state(user_id, concept_id)

       if belief_state.failures_since_reading < INTERVENTION_CONFIG["nudge_threshold"]:
           return None

       if not has_unread_materials_for_concept(user_id, concept_id):
           return None

       unread_count = get_unread_count_for_concept(user_id, concept_id)
       concept = get_concept(concept_id)

       return InterventionNudge(
           type="gentle_nudge",
           concept_id=concept_id,
           concept_name=concept.name,
           unread_count=unread_count,
           message=f"You've missed a few questions on {concept.name}. We have {unread_count} reading material(s) that might help!",
           cta_text="Review Reading",
           cta_url=f"/reading-library?concept_id={concept_id}"
       )
   ```

2. Include in answer submission response:

### AC6: Strong Recommendation Modal (Threshold = 5)

1. After 5th consecutive failure with unread materials, trigger modal intervention:

   def check_strong_intervention(user_id: UUID, concept_id: UUID) -> Optional[InterventionModal]:

       if belief_state.failures_since_reading < INTERVENTION_CONFIG["recommend_threshold"]:

### AC7: Question Selection Deprioritization

1. Modify question selection algorithm (Story 4.2) to consider intervention state:
   ```python
   def calculate_concept_weight(
       user_id: UUID,
       concept_id: UUID,
       base_weight: float
   ) -> float:
       """
       Adjust concept weight based on intervention state.

       If user has failed multiple times on a concept AND has unread materials,
       deprioritize that concept to encourage reading first.
       """
       belief_state = get_belief_state(user_id, concept_id)

       if belief_state.failures_since_reading >= INTERVENTION_CONFIG["deprioritize_threshold"]:
           if has_unread_materials_for_concept(user_id, concept_id):
               # Reduce probability of selecting this concept
               return base_weight * INTERVENTION_CONFIG["deprioritization_factor"]

       return base_weight
   ```

2. This creates natural pressure to address gaps through reading before more questions

3. Deprioritization is lifted immediately when:
   - User completes reading for the concept (resets `failures_since_reading`)
   - OR user answers correctly (resets `consecutive_failures`, though `failures_since_reading` persists)

### AC8: Reading Completion Triggers Reset

1. Hook into reading queue status update (Story 5.8):
   ```python
   @router.put("/api/v1/reading/queue/{queue_id}/status")
   async def update_reading_status(queue_id: UUID, status: ReadingStatus):
       reading_item = get_reading_queue_item(queue_id)
       reading_item.status = status

       if status == ReadingStatus.COMPLETED:
           reading_item.completed_at = datetime.utcnow()

           # Reset intervention counters for all linked concepts
           for concept_id in reading_item.concept_ids:
               reset_intervention_for_concept(
                   user_id=reading_item.user_id,
                   concept_id=concept_id
               )

       db.commit()

   def reset_intervention_for_concept(user_id: UUID, concept_id: UUID):
       belief_state = get_belief_state(user_id, concept_id)
       if belief_state:
           belief_state.failures_since_reading = 0
           belief_state.last_reading_completed_at = datetime.utcnow()

           log.info(
               "Reading intervention reset",
               user_id=user_id,
               concept_id=concept_id
           )
   ```
