# Story 2.14: Belief State Sync for New Concepts

## Status

**Ready for Done**

## Story

**As a** system administrator,
**I want** belief states to be automatically created for existing users when new concepts are added to the system,
**So that** the BKT engine can track mastery for all concepts, including those added after user registration.

## Background

The current `BeliefInitializationService` creates belief states for all concepts when a user first registers. However, when new concepts are added later (e.g., via Story 2.13's `--create-missing-concepts`), existing users don't automatically get belief states for them.

This causes:

1. `BeliefUpdater` to skip concepts without belief states (logs warning, no update)
2. Users unable to have their knowledge tracked for new concepts
3. BKT accuracy degradation as concept coverage grows

## Story Context

**Existing System Integration:**

- Integrates with: `BeliefInitializationService`, `BeliefUpdater`, `BeliefRepository`
- Technology: Python, PostgreSQL, async batch operations
- Follows pattern: Existing belief initialization patterns
- Touch points: User enrollment, concept creation, belief updates

## Acceptance Criteria

### Functional Requirements

1. **Lazy initialization in BeliefUpdater**: When `update_beliefs()` encounters a concept without a belief state, create one with uninformative prior Beta(1,1) before updating
2. **Batch sync script**: `scripts/sync_belief_states.py` to sync all users with all concepts
   ```bash
   python scripts/sync_belief_states.py --course-slug cbap
   ```
3. **Sync on concept creation**: When `--create-missing-concepts` is used in Story 2.13, the import script should:
   - Log a reminder to run `sync_belief_states.py` after import completes
   - Optionally: Call sync function directly if `--sync-beliefs` flag is passed
4. **Uninformative prior**: New belief states use Beta(1,1) = Uniform[0,1] (same as initial registration)
5. **Idempotent sync**: Running sync multiple times has no effect on existing beliefs
6. **Performance**: Sync 1000 users × 50 concepts in <30 seconds
7. **Logging**: Log count of beliefs created per user, total sync duration

### API Endpoint (Optional Enhancement)

8. **POST /api/v1/admin/sync-beliefs**: Admin-only endpoint to trigger belief sync
   - Request: `{ "course_id": "uuid" }`
   - Response: `{ "users_synced": 150, "beliefs_created": 7500, "duration_ms": 5000 }`

### Integration Requirements

9. Existing belief initialization for new users unchanged
10. Existing belief updates for concepts with states unchanged
11. No performance regression in normal quiz flow (<50ms per answer)
12. Compatible with multi-course architecture

### Quality Requirements

13. Unit tests for lazy initialization in BeliefUpdater
14. Unit tests for batch sync logic
15. Integration test: Add new concept, verify user gets belief state on first interaction
16. Performance test: Sync 1000 users × 50 concepts
17. No data loss or corruption of existing beliefs

### Implementation Approach

**Lazy Init Logic (insert after line 112 in update_beliefs):**

```python
# NEW: Lazy initialization for missing beliefs
missing_concept_ids = set(concept_ids) - set(beliefs.keys())
if missing_concept_ids:
    logger.info(
        "Creating missing belief states",
        user_id=str(user_id),
        missing_count=len(missing_concept_ids),
    )
    new_beliefs = await self._create_missing_beliefs(user_id, missing_concept_ids)
    beliefs.update(new_beliefs)
```

**Batch Sync Algorithm:**

1. Get all concepts for course
2. Get all enrolled users
3. For each user: compute `missing = all_concepts - user_beliefs`
4. Batch insert missing with `bulk_create_from_concepts()`
