# Story 2.15: Secondary Tagging for Perspectives and Underlying Competencies

## Status

**Ready for Review**

## Story

**As a** content manager,
**I want** questions to be tagged with BABOK Perspectives and Underlying Competencies as secondary dimensions,
**So that** users can filter questions by these cross-cutting concerns and gain insights into their competency gaps without disrupting the primary KA-based BKT scoring.

## Background

BABOK v3 defines three layers of knowledge:

1. **6 Knowledge Areas (Chapters 2-7)** - Primary assessment dimensions (current implementation)
2. **Underlying Competencies (Chapter 9)** - Cross-cutting skills that enable all KAs
3. **Perspectives (Chapter 10)** - Contextual lenses for applying KAs

Currently, these are mixed into the `concept_tags` column during import. This story separates them into dedicated fields for filtering and analysis while keeping the primary KA-based BKT scoring unchanged.

### Underlying Competencies (Chapter 9)
- Analytical Thinking and Problem Solving
- Behavioral Characteristics
- Business Knowledge
- Communication Skills
- Interaction Skills
- Tools and Technology

### Perspectives (Chapter 10)
- Agile
- Business Intelligence
- Information Technology
- Business Process Management

## Story Context

**Existing System Integration:**
- Integrates with: `scripts/import_vendor_questions.py`, `Question` model, question retrieval APIs
- Technology: Python, PostgreSQL, SQLAlchemy
- Follows pattern: Existing tag parsing in Story 2.13
- Touch points: Question import, question filtering, API responses

**Design Decision:** These are **secondary tags for filtering/analysis**, NOT primary assessment dimensions. BKT belief updates continue to use only the 6 Knowledge Areas.

## Acceptance Criteria

### Functional Requirements

1. **Course Schema**: Add `perspectives` and `competencies` JSONB columns to `courses` table with keyword definitions per course
2. **Question Schema**: Add `perspectives` and `competencies` columns to `questions` table as PostgreSQL ARRAY(String)
3. **Tag Classification**: During import, classify each tag from `concept_tags` as:
   - Concept (routes to concept matching)
   - Competency (routes to `competencies` array)
   - Perspective (routes to `perspectives` array)
4. **Course-Configurable Keywords**: TagClassifier loads keyword lists from course configuration (not hardcoded)
5. **Import Script Update**: Modify `_parse_csv_row()` to classify and route tags using course-specific keywords
6. **Backward Compatibility**: Existing concept tag matching continues to work unchanged
7. **API Filter Parameters**: Add optional `perspectives` and `competencies` query parameters to question retrieval endpoints
8. **Backfill Script**: Create `scripts/backfill_secondary_tags.py` to re-process existing questions

### Multi-Course Support

9. **Course-Specific Definitions**: Each course defines its own perspectives and competencies with keywords
10. **CBAP Seed Data**: Seed CBAP course with BABOK perspectives (Agile, BI, IT, BPM) and competencies (Chapter 9)
11. **Extensible Pattern**: Other courses (PSM1, CFA) can define their own cross-cutting dimensions

### Data Validation

12. **Normalization**: Tags are normalized (lowercase, hyphenated) before classification
13. **Multiple Tags**: Questions can have 0-N perspectives and 0-N competencies
14. **Validation**: API validates perspective/competency values against course configuration

### Quality Requirements

15. Unit tests for tag classification logic with course config
16. Unit tests for keyword matching from JSONB
17. Integration test: Import with mixed tags, verify correct routing
18. Migration test: Backfill existing questions without data loss
19. API test: Filter questions by perspective and competency

**TagClassifier (scripts/import_vendor_questions.py):**
```python
class TagClassifier:
    """Classifies tags into concepts, competencies, or perspectives based on course config."""

    def __init__(self, course: Course):
        """Initialize with course configuration."""
        self.competency_keywords: set[str] = set()
        self.perspective_keywords: set[str] = set()

        # Build keyword sets from course JSONB
        if course.competencies:
            for comp in course.competencies:
                self.competency_keywords.update(kw.lower() for kw in comp.get("keywords", []))

        if course.perspectives:
            for persp in course.perspectives:
                self.perspective_keywords.update(kw.lower() for kw in persp.get("keywords", []))

    def classify_tag(self, tag: str) -> tuple[str, str]:
        """Returns (category, normalized_tag)."""
        normalized = tag.lower().replace("_", "-").strip()

        if any(kw in normalized for kw in self.competency_keywords):
            return ("competency", normalized)
        elif any(kw in normalized for kw in self.perspective_keywords):
            return ("perspective", normalized)
        else:
            return ("concept", tag)  # Keep original for concept matching
```

- Course-configurable keywords allow refinement without code changes
- Logging of classifications for review

- Each course defines its own perspectives/competencies in JSONB
- New courses simply add their definitions to the seed migration
- No hardcoded assumptions about CBAP/BABOK
