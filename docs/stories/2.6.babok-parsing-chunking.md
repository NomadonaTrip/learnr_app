# Story 2.6: Corpus Parsing and Chunking with Concept Links

## Status

Ready for Done

## Story

**As a** content processor,
**I want** to parse course corpus documents (e.g., BABOK v3) and link chunks to concepts within a specific course,
**so that** reading content can be retrieved for specific concept gaps in any course.

## Acceptance Criteria

1. Python script `/scripts/parse_corpus.py` reads corpus PDF (e.g., BABOK v3) **← RENAMED for multi-course**
2. Extract text preserving structure (headings, paragraphs)
3. Chunk using hybrid strategy:
   - Structural: Respect section boundaries
   - Semantic: 200-500 tokens per chunk
4. Chunks table schema (revised for multi-course):
   ```
   - id (UUID, PK)
   - course_id (UUID, FK) **← NEW**
   - title (VARCHAR 255)
   - content (TEXT)
   - corpus_section (VARCHAR 50) - e.g., "3.2.1" **← RENAMED from babok_section**
   - knowledge_area_id (VARCHAR 50) **← RENAMED from knowledge_area, references course JSONB**
   - concept_ids (UUID[]) - array of linked concept IDs
   - estimated_read_time_minutes (INT)
   - chunk_index (INT) - order within section
   - created_at, updated_at
   ```
5. Chunk-concept linking: Map chunks to concepts based on section_ref match **within the same course**
6. Target: 200-500 chunks with concept mappings per course
7. Validation: Each chunk maps to at least 1 concept
8. Distribution: Each KA has 20+ chunks
9. Logs: Chunks created, concept coverage
10. Human review: Export chunks with concept mappings for SME validation
11. **Multi-course:** Script accepts `--course-slug` to scope parsing to a specific course **← NEW**

### Knowledge Area Mapping (Dynamic from Course)

```python
async def get_ka_mapping(course: Course) -> Dict[str, str]:
    """Build section→KA mapping from course knowledge_areas JSONB."""
    # CBAP example: knowledge_areas contains section prefixes
    # {"id": "ba-planning", "name": "...", "section_prefix": "3"}
    return {
        ka["section_prefix"]: ka["id"]
        for ka in course.knowledge_areas
        if "section_prefix" in ka
    }

def get_ka_from_section(section_ref: str, ka_mapping: Dict[str, str]) -> str:
    """Get Knowledge Area ID from section reference."""
    first_digit = section_ref.split('.')[0]
    return ka_mapping.get(first_digit, "unknown")
```

### Hybrid Chunking Strategy

```python
import tiktoken

enc = tiktoken.get_encoding("cl100k_base")

def chunk_section(
    section: BabokSection,
    min_tokens: int = 200,
    max_tokens: int = 500,
    overlap_tokens: int = 50
) -> List[Chunk]:
    """
    Chunk a section using hybrid strategy.

    Rules:
    1. Never split across section boundaries
    2. Target 200-500 tokens per chunk
    3. Prefer splitting at paragraph boundaries
    4. Add 50-token overlap for context
    """
    paragraphs = section.content.split('\n\n')
    chunks = []
    current_chunk = []
    current_tokens = 0

    for para in paragraphs:
        para_tokens = len(enc.encode(para))

        if current_tokens + para_tokens > max_tokens and current_chunk:
            # Emit current chunk
            chunks.append(Chunk(
                content='\n\n'.join(current_chunk),
                tokens=current_tokens
            ))

            # Start new chunk with overlap
            overlap_text = get_overlap(current_chunk, overlap_tokens)
            current_chunk = [overlap_text, para] if overlap_text else [para]
            current_tokens = len(enc.encode('\n\n'.join(current_chunk)))
        else:
            current_chunk.append(para)
            current_tokens += para_tokens

    # Emit final chunk
    if current_chunk:
        chunks.append(Chunk(
            content='\n\n'.join(current_chunk),
            tokens=current_tokens
        ))

    return chunks
```

### Concept Linking Logic

```python
def link_chunk_to_concepts(
    chunk_section_ref: str,
    concepts: List[Concept],
    course_id: UUID  # NEW - ensure same course
) -> List[UUID]:
    """
    Link a chunk to concepts based on section reference.

    Matching rules:
    1. Course filter: Only concepts from same course
    2. Exact match: chunk 3.2.1 → concept 3.2.1
    3. Parent match: chunk 3.2.1 → concept 3.2 (parent)
    4. Child match: chunk 3.2 → concepts 3.2.1, 3.2.2 (children)
    """
    matched_ids = []

    for concept in concepts:
        # Filter by course
        if concept.course_id != course_id:
            continue

        concept_ref = concept.corpus_section_ref  # RENAMED from babok_section_ref

        # Exact match
        if concept_ref == chunk_section_ref:
            matched_ids.append(concept.id)
            continue

        # Chunk is child of concept (parent match)
        if chunk_section_ref.startswith(concept_ref + '.'):
            matched_ids.append(concept.id)
            continue

        # Concept is child of chunk (child match)
        if concept_ref.startswith(chunk_section_ref + '.'):
            matched_ids.append(concept.id)
            continue

    return matched_ids
```

### Security Review

**Status: PASS with one CONCERN**

✓ **Strengths:**
- SQL Injection: No risk - SQLAlchemy ORM used exclusively (repository pattern throughout)
- XSS: N/A - server-side only, no user-generated HTML
- UUID Primary Keys: Non-enumerable IDs prevent ID guessing attacks (migration:26)
- Cascade Delete: Proper ON DELETE CASCADE ensures no orphaned data (migration:38)
- Input Validation: Pydantic schemas validate all inputs (schemas/reading_chunk.py)
- Course Isolation: Multi-course filtering prevents cross-course data leakage (repository:100, 122, 143, linking:352-354)

⚠ **CONCERN: PDF DoS Attack Vector**
- **Issue**: No file size validation on PDF uploads
- **Risk**: Malicious actors could submit arbitrarily large PDFs (multi-GB) causing memory exhaustion or excessive processing time
- **Location**: parse_corpus.py:630-633 validates existence but not size
- **Recommendation**: Add file size check before parsing:
  ```python
  pdf_size_mb = pdf_path.stat().st_size / (1024 * 1024)
  if pdf_size_mb > 100:  # 100MB limit
      logger.error(f"PDF too large: {pdf_size_mb:.1f}MB")
      sys.exit(1)
  ```
- **Priority**: Medium (script is internal/admin-facing, not public API)
- **Mitigation**: Document maximum PDF size in ops runbook
