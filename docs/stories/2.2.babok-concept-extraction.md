# Story 2.2: BABOK v3 Concept Extraction

## Status

Ready for Review

## Story

**As a** knowledge engineer,
**I want** to extract discrete, testable concepts from BABOK v3 and store them scoped to the CBAP course,
**so that** the BKT engine can track mastery at the concept level for the CBAP certification.

## Acceptance Criteria

1. Python script `/scripts/extract_babok_concepts.py` parses BABOK v3 PDF
2. Extract concepts using hybrid approach:
   - **Structural extraction:** Each numbered section (e.g., 3.2.1) represents one or more concepts
   - **Semantic extraction:** Within sections, identify distinct testable knowledge units
   - **NLP assistance:** Use GPT-4 to identify concept boundaries and names
3. Concept schema in PostgreSQL `concepts` table with **multi-course support**:
   ```
   - id (UUID, PK)
   - course_id (UUID, FK to courses) - REQUIRED for multi-course
   - name (VARCHAR 255) - e.g., "Stakeholder Identification"
   - description (TEXT) - 1-2 sentence definition
   - corpus_section_ref (VARCHAR 50) - e.g., "3.2.1" (was babok_section_ref)
   - knowledge_area_id (VARCHAR 50) - matches course.knowledge_areas[].id
   - difficulty_estimate (FLOAT 0.0-1.0) - based on section depth/complexity
   - prerequisite_depth (INT) - distance from root concepts (0 = foundational)
   - created_at, updated_at
   ```
4. Target: 500-1500 concepts extracted (granular enough for BKT, not too granular)
5. Distribution: Each KA has 75-250 concepts (balanced coverage)
6. Concept naming convention: Clear, specific, testable (e.g., "RACI Matrix Construction" not "RACI")
7. Human review checkpoint: Export concepts to CSV for SME validation before proceeding
8. Script logs: Total concepts extracted, breakdown by KA, section coverage percentage
9. Validation: 95%+ of BABOK sections have at least one concept mapped
10. Concepts stored in PostgreSQL with proper indexing, scoped to CBAP course_id

### Multi-Course Architecture Alignment

**CRITICAL CHANGES from original story:**

| Field               | Original              | Multi-Course                                             |
| ------------------- | --------------------- | -------------------------------------------------------- |
| `course_id`         | Not present           | `UUID NOT NULL REFERENCES courses(id)`                   |

**Why these changes matter:**

1. Concepts are scoped to a course - allows PSM1, PMP, etc. in future
2. `knowledge_area_id` matches course JSONB keys for dynamic KA support
3. `corpus_section_ref` is generic (BABOK, Scrum Guide, PMBOK, etc.)

### Database Schema Reference

[Source: architecture/database-schema.md#concepts]

```sql
CREATE TABLE concepts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    course_id UUID NOT NULL REFERENCES courses(id) ON DELETE CASCADE,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    corpus_section_ref VARCHAR(50),          -- Was babok_section_ref
    knowledge_area_id VARCHAR(50) NOT NULL,  -- References course.knowledge_areas[].id
    difficulty_estimate FLOAT NOT NULL DEFAULT 0.5,
    prerequisite_depth INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_concepts_course ON concepts(course_id);
CREATE INDEX idx_concepts_knowledge_area ON concepts(course_id, knowledge_area_id);
CREATE INDEX idx_concepts_section ON concepts(corpus_section_ref);
```

```python
def map_ka_name_to_id(ka_name: str, course_knowledge_areas: List[dict]) -> str:
    """Map BABOK KA name to course knowledge_area_id."""
    for ka in course_knowledge_areas:
        if ka["name"] == ka_name:
            return ka["id"]
    raise ValueError(f"Unknown KA: {ka_name}")
```

**Recommended Prompt Template:**

```python
CONCEPT_EXTRACTION_PROMPT = """
Given this BABOK v3 section, identify distinct testable concepts.

Section: {section_number} - {section_title}
Knowledge Area: {knowledge_area}
Content:
{section_content}

For each concept, provide:
1. name: Clear, specific, testable name (e.g., "RACI Matrix Construction" not "RACI")
2. description: 1-2 sentence definition that explains what the learner should know
3. difficulty_estimate: 0.0-1.0 (0.0 = foundational, 1.0 = advanced)

Output as JSON array:
[
  {
    "name": "Concept Name",
    "description": "What the learner should understand...",
    "difficulty_estimate": 0.5
  }
]

Rules:
- Each concept must represent a single, distinct piece of knowledge
- Concepts must be testable with a multiple-choice question
- Avoid overly broad concepts (e.g., "Business Analysis" is too broad)
- Avoid overly narrow concepts (e.g., "RACI Matrix Row 3" is too narrow)
- Target 3-10 concepts per major section, 1-3 per minor section
"""
```

### Error Handling

- **PDF Parse Errors:** Log and skip problematic pages, continue extraction
- **GPT-4 API Errors:** Retry with exponential backoff (max 3 retries)
- **Rate Limits:** Implement token bucket or sliding window
- **Database Errors:** Rollback transaction, log error, exit with error code
- **Validation Failures:** Log warnings but complete extraction (unless critical)
- **Course Not Found:** Exit with error if CBAP course not in database (Story 2.0 dependency)
