# Story 2.16: Non-Conventional KA Mapping for Import

## Status

**Ready for Done**

## Story

**As a** content manager,
**I want** questions with non-conventional KA values (Perspectives and Underlying Competencies) to be automatically mapped to appropriate primary Knowledge Areas during import,
**So that** all vendor questions can participate in BKT scoring while preserving their original classification as secondary tags.

## Background

BABOK v3 defines three layers of knowledge that appear in vendor question CSVs:

1. **6 Knowledge Areas (Chapters 2-7)** - Primary BKT scoring dimensions
2. **Underlying Competencies (Chapter 9)** - Cross-cutting skills (20 questions in sample)
3. **Perspectives (Chapter 10)** - Contextual lenses (25 questions in sample)

Currently, the import script skips questions with non-conventional KA values because they don't map to the 6 primary KAs. This means ~18% of vendor questions (45/246) cannot be imported.

### Non-Conventional KA Values in CSV

| KA Value                                  | Count | Category   |
| ----------------------------------------- | ----- | ---------- |
| `Underlying Competencies`                 | 20    | Chapter 9  |
| `Agile Perspective`                       | 5     | Chapter 10 |
| `Business Intelligence Perspective`       | 5     | Chapter 10 |

### Mapping Strategy

**Perspectives → Primary KA (rule-based):**

| Perspective                             | Primary KA      | Rationale                                                  |
| --------------------------------------- | --------------- | ---------------------------------------------------------- |
| Agile Perspective                       | `strategy`      | Agile is a strategic approach to delivering change         |
| Business Intelligence Perspective       | `solution-eval` | BI focuses on measuring and analyzing solution performance |
| Business Process Management Perspective | `radd`          | BPM involves designing and modeling processes              |
| Information Technology Perspective      | `radd`          | IT perspective applies to requirements and design          |
| Business Architecture Perspective       | `strategy`      | Business architecture aligns with strategic analysis       |

**Underlying Competencies → Primary KA (tag-inferred):**

Analyze `concept_tags` to infer the most appropriate KA:

- Tags containing elicitation/communication keywords → `elicitation`
- Tags containing strategy/conceptual keywords → `strategy`
- Tags containing decision/prioritization keywords → `rlcm`
- Tags containing modeling/design keywords → `radd`
- Fallback: `ba-planning` (competencies are foundational to planning)

**Competency ID Extraction:**

When `ka` = "Underlying Competencies", the `concept_tags` column contains the specific competency name(s) being tested. Example CSV rows:

| ka                      | concept_tags                                 | Extracted Competency IDs |
| ----------------------- | -------------------------------------------- | ------------------------ |
| Underlying Competencies | `Conceptual-Thinking,Strategy-Alignment`     | `["analytical"]`         |
| Underlying Competencies | `Creative-Thinking`                          | `["analytical"]`         |
| Underlying Competencies | `Communication-Skills,Written-Communication` | `["communication"]`      |
| Underlying Competencies | `Systems-Thinking,Visual-Thinking`           | `["analytical"]`         |
| Underlying Competencies | `Adaptability,Methodology-Knowledge`         | `["behavioral"]`         |

The `TagClassifier` (from Story 2.15) already matches tags against `course.competencies` keywords and returns competency IDs. For "Underlying Competencies" questions, this extraction happens automatically via the existing tag classification flow.

## Acceptance Criteria

### Functional Requirements

1. **Perspective KA Mapping**: When `ka` column contains a perspective value (e.g., "Agile Perspective"), map to the configured primary KA and add the perspective ID to `perspectives` array
2. **Competency KA Mapping**: When `ka` column contains "Underlying Competencies":
   - Infer primary KA from `concept_tags` using keyword matching (see AC 8-13)
   - Extract competency IDs via `TagClassifier.classify_tags()` which matches tags against `course.competencies` keywords
   - Add extracted competency IDs to `competencies` array
3. **Fallback Handling**: If tag-based KA inference fails for competencies, use `ba-planning` as default and log a warning. If no competency IDs are extracted from tags, log a warning but continue import.
4. **Course-Configurable Mappings**: Perspective-to-KA mappings are stored in course JSONB (not hardcoded)
5. **Preserve Original Classification**: Store original KA value in `original_ka` question metadata (optional) or rely on secondary tags
6. **Import Success**: All 246 sample questions import successfully (no skipped due to unknown KA)
7. **Logging**: Log each non-conventional KA mapping at INFO level for auditability

### Tag Inference Rules for Competencies

8. **Elicitation Keywords**: Tags containing `elicitation`, `interview`, `workshop`, `collaboration`, `communication`, `facilitation` → `elicitation`
9. **Strategy Keywords**: Tags containing `strategy`, `conceptual`, `systems-thinking`, `business-acumen`, `industry` → `strategy`
10. **RLCM Keywords**: Tags containing `decision`, `prioritiz`, `approval`, `traceability`, `change` → `rlcm`
11. **RADD Keywords**: Tags containing `model`, `design`, `data`, `analysis`, `specification` → `radd`
12. **Solution Eval Keywords**: Tags containing `evaluation`, `metric`, `performance`, `assessment` → `solution-eval`
13. **Default**: No keyword match → `ba-planning`

### Edge Case Handling

14. **Case Insensitivity**: KA matching is case-insensitive (e.g., "AGILE PERSPECTIVE", "Agile Perspective", "agile perspective" all match)
15. **Partial Perspective Matches**: Match perspective by name with or without "Perspective" suffix:
    - "Agile Perspective" → matches `agile`
    - "Agile" → matches `agile`
    - "Business Intelligence" → matches `bi`
16. **Whitespace Normalization**: Leading/trailing whitespace is stripped before matching
17. **Unknown Non-Conventional KA**: If a KA looks like a perspective but doesn't match any configured perspective, log warning and fall back to `ba-planning`

### Data Validation

18. **Secondary Tag Population**: Questions with perspective KAs get `perspectives` array populated
19. **Secondary Tag Population**: Questions with competency KAs get `competencies` array populated
20. **Existing Behavior Unchanged**: Questions with standard 6 KAs import exactly as before

### Quality Requirements

21. Unit tests for `KAMapper` class with perspective mappings (including edge cases)
22. Unit tests for `KAMapper` class with competency tag inference
23. Integration test: Import CSV with mixed KA types, verify all import successfully
24. Integration test: Verify secondary tags are correctly populated
25. Regression test: Standard KA questions unchanged

**KAMapper Class (scripts/import_vendor_questions.py):**

```python
class KAMapper:
    """Maps non-conventional KA values to primary KAs for BKT scoring."""

    # Competency tag inference keywords
    ELICITATION_KEYWORDS = {'elicitation', 'interview', 'workshop', 'collaboration',
                            'communication', 'facilitation', 'listening'}
    STRATEGY_KEYWORDS = {'strategy', 'conceptual', 'systems-thinking', 'business-acumen',
                         'industry', 'organization', 'vision'}
    RLCM_KEYWORDS = {'decision', 'prioritiz', 'approval', 'traceability', 'change',
                     'governance', 'baseline'}
    RADD_KEYWORDS = {'model', 'design', 'data', 'analysis', 'specification',
                     'diagram', 'prototype'}
    SOLUTION_EVAL_KEYWORDS = {'evaluation', 'metric', 'performance', 'assessment',
                              'measure', 'kpi'}

    def __init__(self, course: Course):
        """Load perspective-to-KA mappings from course config."""
        self.perspective_to_ka: Dict[str, str] = {}  # persp_id -> primary_ka
        self.perspective_name_to_id: Dict[str, str] = {}  # normalized name -> persp_id

        if course.perspectives:
            for persp in course.perspectives:
                persp_id = persp.get("id", "")
                primary_ka = persp.get("primary_ka", "ba-planning")
                name = persp.get("name", "").lower().strip()

                self.perspective_to_ka[persp_id] = primary_ka

                # AC 14-16: Case-insensitive, partial matches, whitespace normalized
                # Register multiple variants for flexible matching:
                self.perspective_name_to_id[name] = persp_id                    # "agile"
                self.perspective_name_to_id[f"{name} perspective"] = persp_id   # "agile perspective"
                self.perspective_name_to_id[persp_id] = persp_id                # "agile" (by id)

    def is_non_conventional_ka(self, ka_name: str) -> bool:
        """Check if KA is a perspective or competency category (AC 14-16)."""
        normalized = ka_name.lower().strip()
        if normalized == "underlying competencies":
            return True
        # Check against all registered perspective name variants
        return normalized in self.perspective_name_to_id

    def infer_ka_from_tags(self, tags: List[str]) -> str:
        """Infer primary KA from concept tags for competency questions."""
        tag_text = " ".join(t.lower() for t in tags)

        if any(kw in tag_text for kw in self.ELICITATION_KEYWORDS):
            return "elicitation"
        if any(kw in tag_text for kw in self.STRATEGY_KEYWORDS):
            return "strategy"
        if any(kw in tag_text for kw in self.RLCM_KEYWORDS):
            return "rlcm"
        if any(kw in tag_text for kw in self.RADD_KEYWORDS):
            return "radd"
        if any(kw in tag_text for kw in self.SOLUTION_EVAL_KEYWORDS):
            return "solution-eval"

        return "ba-planning"  # Default fallback

    def map_ka(self, ka_name: str, concept_tags: List[str]) -> Tuple[str, Optional[str]]:
        """
        Map non-conventional KA to primary KA.

        Args:
            ka_name: The KA value from CSV (e.g., "Agile Perspective", "Underlying Competencies")
            concept_tags: List of concept tags for KA inference

        Returns:
            Tuple of (primary_ka_id, perspective_id or None)
            - For perspectives: (mapped_ka, perspective_id)
            - For competencies: (inferred_ka, None)  # competency IDs come from TagClassifier
        """
        # AC 14-16: Case-insensitive, whitespace normalized
        normalized = ka_name.lower().strip()

        # Handle "Underlying Competencies" - infer KA from tags
        if normalized == "underlying competencies":
            inferred_ka = self.infer_ka_from_tags(concept_tags)
            logger.debug(f"Inferred KA '{inferred_ka}' from tags for 'Underlying Competencies'")
            return (inferred_ka, None)

        # AC 15: Handle perspective KAs - supports partial matches ("Agile" or "Agile Perspective")
        if normalized in self.perspective_name_to_id:
            persp_id = self.perspective_name_to_id[normalized]
            primary_ka = self.perspective_to_ka[persp_id]
            logger.debug(f"Mapped perspective '{ka_name}' → KA '{primary_ka}', perspective_id '{persp_id}'")
            return (primary_ka, persp_id)

        # AC 17: Fallback for unknown non-conventional KA
        logger.warning(f"Unknown non-conventional KA: '{ka_name}', defaulting to 'ba-planning'")
        return ("ba-planning", None)
```
