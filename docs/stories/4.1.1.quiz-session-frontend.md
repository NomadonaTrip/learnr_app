# Story 4.1.1: Quiz Session Frontend

## Status

**Ready for Review**

---

## Story

**As a** user who completed the diagnostic assessment,
**I want** to start an adaptive quiz session from the results page,
**so that** I can practice questions optimally selected for my knowledge gaps.

---

## Acceptance Criteria

1. Clicking "Start Adaptive Quiz" on diagnostic results navigates to `/quiz`
2. Quiz page calls `POST /api/v1/quiz/session/start` on mount
3. If existing active session found (`is_resumed: true`), display "Resuming session..." message
4. If new session created, display "Starting new session..." then transition to ready state
5. Quiz page displays session info: session type, question strategy, status
6. Session can be paused via "Pause" button (calls `POST /api/v1/quiz/session/{id}/pause`)
7. Paused session shows "Session Paused" state with "Resume" button
8. Session can be ended via "End Session" button (calls `POST /api/v1/quiz/session/{id}/end`)
9. Ended session navigates to results/summary page (placeholder for now)
10. Error states handled gracefully (no enrollment, API errors)
11. Loading states shown during API calls
12. Follows accessibility standards (keyboard navigation, ARIA labels)

### Architecture Context

This story implements the **frontend** for Quiz Session Management, connecting to the backend API created in Story 4.1. It provides the user interface for starting, pausing, resuming, and ending quiz sessions.

**Dependencies:**
- Story 4.1 (Quiz Session Backend) - MUST BE COMPLETE - provides API endpoints

**Provides for:**

[Source: docs/prd/epic-4-bkt.md - Story 4.1]

### Backend API Endpoints (From Story 4.1)

```
POST /api/v1/quiz/session/start
  Request: { session_type?, question_strategy?, knowledge_area_filter? }
  Response: { session_id, session_type, question_strategy, is_resumed, status, started_at, total_questions, correct_count, first_question }

GET /api/v1/quiz/session/{id}
  Response: { id, session_type, question_strategy, status, is_paused, started_at, ended_at, total_questions, correct_count, accuracy, version }

POST /api/v1/quiz/session/{id}/pause
  Response: { session_id, status, is_paused }

POST /api/v1/quiz/session/{id}/resume
  Response: { session_id, status, is_paused }

POST /api/v1/quiz/session/{id}/end
  Request: { expected_version }
  Response: { session_id, ended_at, total_questions, correct_count, accuracy }
```

[Source: Story 4.1 implementation]
