# Story 3.6: Diagnostic Assessment UI

## Status

**Ready for Review**

---

## Story

**As a** new user,
**I want** to complete the diagnostic assessment in a focused interface,
**so that** my initial knowledge state can be measured.

---

## Acceptance Criteria

1. Navigate to `/diagnostic` after account creation
2. Fetch questions from GET `/api/v1/diagnostic/questions`
3. Display one question at a time (full-screen, minimal chrome)
4. Question display: Question text, 4 options (A/B/C/D as pill buttons)
5. Progress indicator: "Question X of {total}" + concept coverage meter
6. User selects option -> "Submit Answer" button enabled
7. On submit: POST `/api/v1/diagnostic/answer` with question_id and selected_answer
8. **No immediate feedback** during diagnostic (different from quiz mode)
9. Auto-advance to next question after submission
10. 30-minute session timeout with warning at 25 minutes
11. No back button (can't change previous answers)
12. Browser navigation blocked with confirmation dialog
13. After last question -> trigger belief update and redirect to results
14. Accessibility: Keyboard navigation, screen reader support
15. Mobile responsive (375px minimum)

**UI Additions for BKT:**

- Concept coverage meter (optional): Shows % of corpus touched
- "Building your knowledge profile..." messaging

## Dev Notes

### Architecture Context

This story implements the **Diagnostic Assessment UI** - a focused, full-screen interface for new users to complete their initial diagnostic assessment. The diagnostic uses questions selected by Story 3.5's optimal selection algorithm and updates belief states via Story 3.7's BKT engine.

> **BLOCKED BY: Story 3.5 (Optimal Diagnostic Question Selection)**
> This story requires the `GET /api/v1/diagnostic/questions` endpoint provided by Story 3.5. Development can proceed with mock data, but integration testing requires Story 3.5 completion.

> **API ENDPOINTS CONFIRMED:**
> This story uses **diagnostic-specific endpoints** (not the quiz endpoints). These are intentionally separate from `/quiz/*` endpoints because:
>
> - Diagnostic returns batch of pre-selected questions (GET), not per-question selection (POST)
> - Diagnostic answer response excludes correctness feedback (no `is_correct`, no `explanation`)
> - Response contract differs: `{is_recorded, concepts_updated, diagnostic_progress, diagnostic_total}`
>
> | Endpoint                           | Provided By | Contract                                       |
> | ---------------------------------- | ----------- | ---------------------------------------------- |
> | `GET /api/v1/diagnostic/questions` | Story 3.5   | Returns optimally-selected question batch      |
> | `POST /api/v1/diagnostic/answer`   | Story 3.7   | Records answer, returns progress (no feedback) |
> | `GET /api/v1/diagnostic/results`   | Story 3.8   | Returns diagnostic results summary             |
>
> [Source: docs/prd/epic-3-bkt.md - Stories 3.5, 3.6, 3.7, 3.8]

**Key Difference from Quiz Mode:**

- **No immediate feedback** - Users don't see if they're correct/incorrect during diagnostic
- **No back button** - Forward-only flow to prevent gaming the assessment
- **Session timeout** - 30-minute limit to ensure focused completion

[Source: docs/prd/epic-3-bkt.md#story-36]

### Browser Navigation Blocking

Prevent accidental navigation away from the diagnostic:

```tsx
// apps/web/src/pages/DiagnosticPage.tsx
useEffect(() => {
  const handleBeforeUnload = (e: BeforeUnloadEvent) => {
    if (diagnosticInProgress && !isComplete) {
      e.preventDefault();
      e.returnValue = "Your diagnostic progress will be lost. Are you sure?";
      return e.returnValue;
    }
  };

  window.addEventListener("beforeunload", handleBeforeUnload);
  return () => window.removeEventListener("beforeunload", handleBeforeUnload);
}, [diagnosticInProgress, isComplete]);
```

Also block React Router navigation:

```tsx
import { useBlocker } from "react-router-dom";

const blocker = useBlocker(
  ({ currentLocation, nextLocation }) =>
    diagnosticInProgress &&
    !isComplete &&
    currentLocation.pathname !== nextLocation.pathname
);

// Show confirmation dialog when blocker.state === 'blocked'
```

### Session Timeout Implementation

30-minute timer with 5-minute warning:

```tsx
// apps/web/src/components/diagnostic/SessionTimer.tsx
const TOTAL_TIME_MS = 30 * 60 * 1000; // 30 minutes
const WARNING_TIME_MS = 25 * 60 * 1000; // 25 minutes (5 min remaining)

export function SessionTimer({ onTimeout, onWarning }: SessionTimerProps) {
  const [elapsedMs, setElapsedMs] = useState(0);
  const [showWarning, setShowWarning] = useState(false);

  useEffect(() => {
    const interval = setInterval(() => {
      setElapsedMs((prev) => {
        const newElapsed = prev + 1000;

        if (newElapsed >= WARNING_TIME_MS && !showWarning) {
          setShowWarning(true);
          onWarning?.();
        }

        if (newElapsed >= TOTAL_TIME_MS) {
          onTimeout();
          clearInterval(interval);
        }

        return newElapsed;
      });
    }, 1000);

    return () => clearInterval(interval);
  }, [onTimeout, onWarning, showWarning]);

  const remainingMs = TOTAL_TIME_MS - elapsedMs;
  const minutes = Math.floor(remainingMs / 60000);
  const seconds = Math.floor((remainingMs % 60000) / 1000);

  return (
    <div className="text-sm text-gray-500">
      Time remaining: {minutes}:{seconds.toString().padStart(2, "0")}
      {showWarning && (
        <div
          role="alert"
          aria-live="assertive"
          className="text-warning-600 font-medium"
        >
          5 minutes remaining!
        </div>
      )}
    </div>
  );
}
```

test.describe("Diagnostic Assessment", () => {
  test.beforeEach(async ({ page }) => {
    // Login and navigate to diagnostic
    await page.goto("/login");
    // ... login steps
    await page.goto("/diagnostic");
  });

  test("completes full diagnostic flow", async ({ page }) => {
    // Verify questions load
    await expect(page.getByRole("heading", { level: 2 })).toBeVisible();
    await expect(page.getByText("Question 1 of")).toBeVisible();

    // Answer all questions
    for (let i = 1; i <= 15; i++) {
      await page.getByRole("radio", { name: /^A\./ }).click();
      await page.getByRole("button", { name: "Submit Answer" }).click();

      if (i < 15) {
        await expect(page.getByText(`Question ${i + 1} of`)).toBeVisible();
      }
    }

    // Verify redirect to results
    await expect(page).toHaveURL("/diagnostic/results");
  });

  test("blocks navigation during diagnostic", async ({ page }) => {
    // Start diagnostic
    await expect(page.getByText("Question 1 of")).toBeVisible();

    // Attempt to navigate away
    page.on("dialog", async (dialog) => {
      expect(dialog.message()).toContain("progress will be lost");
      await dialog.dismiss();
    });

    await page.goto("/dashboard");

    // Should still be on diagnostic
    await expect(page).toHaveURL("/diagnostic");
  });

  test("keyboard navigation works", async ({ page }) => {
    // Focus first option
    await page.keyboard.press("Tab");

    // Navigate with arrow keys
    await page.keyboard.press("ArrowDown");
    await page.keyboard.press("ArrowDown");

    // Select with Enter
    await page.keyboard.press("Enter");

    // Tab to submit and press Enter
    await page.keyboard.press("Tab");
    await page.keyboard.press("Enter");

    // Verify advancement
    await expect(page.getByText("Question 2 of")).toBeVisible();
  });
});
