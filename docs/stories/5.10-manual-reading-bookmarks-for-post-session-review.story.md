# Story 5.10: Manual Reading Bookmarks for Post-Session Review

## Status

**Approved**

## Story

**As a** user reviewing incorrect answers,
**I want to** manually bookmark specific reading materials during post-session review for later study,
**so that** I can save high-priority content separately from the automatic reading queue.

## Context

This story complements the automatic reading queue (Stories 5.5-5.9) by allowing users to explicitly bookmark materials they find particularly valuable during the post-session review phase. While the reading queue is auto-populated, bookmarks are user-initiated and signify higher intent to study specific content.

## Acceptance Criteria

1. **Database Schema:** Create `reading_bookmarks` table with the following structure:

   ```sql
   CREATE TABLE reading_bookmarks (
       bookmark_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
       enrollment_id UUID NOT NULL REFERENCES enrollments(id) ON DELETE CASCADE,
       chunk_id UUID NOT NULL REFERENCES reading_chunks(id) ON DELETE CASCADE,
       question_id UUID REFERENCES questions(id) ON DELETE SET NULL,
       session_id UUID REFERENCES quiz_sessions(id) ON DELETE SET NULL,
       review_id UUID REFERENCES review_sessions(id) ON DELETE SET NULL,
       is_read BOOLEAN DEFAULT FALSE,
       read_at TIMESTAMP,
       bookmarked_at TIMESTAMP NOT NULL DEFAULT NOW(),
       CONSTRAINT unique_user_chunk_bookmark UNIQUE (user_id, chunk_id)
   );

   CREATE INDEX idx_reading_bookmarks_user ON reading_bookmarks(user_id);
   CREATE INDEX idx_reading_bookmarks_enrollment ON reading_bookmarks(enrollment_id);
   CREATE INDEX idx_reading_bookmarks_unread ON reading_bookmarks(user_id, is_read) WHERE is_read = FALSE;
   ```

   **Note:** `review_sessions` table is created by Story 4.9. The `review_id` FK is optional and will be populated when bookmarking from a review session context.

2. **POST `/api/v1/reading/bookmarks` endpoint** - Create new bookmark
   - Request body: `{"enrollment_id": "uuid", "chunk_id": "uuid", "question_id": "uuid", "session_id": "uuid", "review_id": "uuid"}`
   - Response: `201 Created` with `{"bookmark_id": "uuid", "chunk_id": "uuid", "bookmarked_at": "ISO8601", "is_new": true}`
   - Response for duplicate: `200 OK` with `{"bookmark_id": "uuid", "chunk_id": "uuid", "bookmarked_at": "ISO8601", "is_new": false}`
   - Validation: Duplicate bookmarks return existing bookmark (idempotent), not 409 error
   - Business logic: Bookmarks exist independently from reading_queue. A chunk can be in both tables simultaneously (queue = system-recommended, bookmark = user-saved)

3. **GET `/api/v1/reading/bookmarks` endpoint** - Retrieve user's bookmarks
   - Query parameters:
     - `unread_only=true|false` (default: false) - Filter to unread bookmarks only
     - `ka_id=uuid` (optional) - Filter by Knowledge Area
     - `page=1` and `per_page=20` (pagination)
   - Response: Array of bookmark objects including:
     - `bookmark_id`, `chunk_id`, `title` (BABOK section name), `preview` (first 100 chars)
     - `babok_section` (e.g., "3.2.1"), `ka_name`, `word_count`, `estimated_read_minutes`
     - Context: `question_preview`, `session_id`, `review_id`, `bookmarked_at`
     - `is_read`, `read_at`
   - Pagination metadata: `total_items`, `total_pages`, `current_page`

4. **PUT `/api/v1/reading/bookmarks/{bookmark_id}/mark-read` endpoint** - Mark bookmark as read
   - Request: No body required
   - Response: `200 OK` with `{"bookmark_id": "uuid", "is_read": true, "read_at": "ISO8601"}`
   - Business logic: Set `is_read = TRUE`, `read_at = NOW()`

5. **DELETE `/api/v1/reading/bookmarks/{bookmark_id}` endpoint** - Remove bookmark
   - Response: `204 No Content`
   - Business logic: Hard delete for MVP simplicity

6. **Frontend Integration in Post-Session Review:**
   - When displaying reading material during review (Story 4.9), add "Save for Later" button next to each chunk
   - Clicking "Save for Later" → POST to `/api/v1/reading/bookmarks` → Visual confirmation ("Bookmarked!")
   - If chunk already bookmarked → show "Bookmarked ✓" (disabled state)

7. **Bookmarks Page/Section in Navigation:**
   - Add "Bookmarks" link in navigation (separate from "Reading Library")
   - Bookmarks page displays user's saved materials using GET `/api/v1/reading/bookmarks`
   - Tabs: "Unread Bookmarks" (default) | "All Bookmarks"
   - Each bookmark card shows same design as reading queue but with bookmark icon
   - Actions: "Read Now", "Mark as Read", "Remove Bookmark"

8. **Distinction from Reading Queue:**
   - Reading Queue (`reading_queue` table): Auto-populated, system-driven recommendations
   - Reading Bookmarks (`reading_bookmarks` table): User-initiated, manually saved high-value materials
   - Both can coexist: A chunk can be in both queue AND bookmarks (separate tables)
   - User benefit: Bookmarks provide a "favorites" layer on top of the queue

9. **Analytics Tracking:**
   - Track bookmark creation rate: % of displayed reading chunks that get bookmarked
   - Track bookmark read rate: % of bookmarks that get marked as read (target: 70%+)
   - Compare engagement: Bookmarked items should have higher completion rate than queue items

10. **Unit Tests:**
    - Create bookmark, retrieve bookmarks, mark as read, remove bookmark
    - Idempotent bookmark creation (duplicate returns existing)
    - Pagination works correctly
    - Filtering by unread_only and ka_id works

11. **Integration Tests:**
    - Full bookmark flow: Create → Retrieve → Mark Read → Delete
    - Bookmark during review session updates bookmarks list
    - Bookmarks persist across sessions

12. **Performance:**
    - Bookmark queries optimized with indexes on `user_id` and `is_read`
    - GET `/api/v1/reading/bookmarks` returns in <200ms for up to 100 bookmarks per user

## Dev Notes

### API Specifications

**POST `/api/v1/reading/bookmarks`**

Creates a new bookmark or returns existing.

**Request:**

```json
{
  "enrollment_id": "uuid",
  "chunk_id": "uuid",
  "question_id": "uuid",
  "session_id": "uuid",
  "review_id": "uuid"
}
```

**Response (201 Created - new bookmark):**

```json
{
  "bookmark_id": "uuid",
  "chunk_id": "uuid",
  "bookmarked_at": "2025-12-24T10:30:00Z",
  "is_new": true
}
```

**Response (200 OK - existing bookmark):**

```json
{
  "bookmark_id": "uuid",
  "chunk_id": "uuid",
  "bookmarked_at": "2025-12-24T10:30:00Z",
  "is_new": false
}
```

**Error Responses:**

| Status | Description |
|--------|-------------|
| 400 Bad Request | Invalid UUID format or missing required fields |
| 401 Unauthorized | Missing or invalid JWT token |
| 404 Not Found | `chunk_id` or `enrollment_id` does not exist |

**GET `/api/v1/reading/bookmarks`**

Retrieves user's bookmarks with optional filters.

**Query Parameters:**
| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `unread_only` | boolean | false | Filter to unread bookmarks |
| `ka_id` | uuid | - | Filter by Knowledge Area |
| `page` | int | 1 | Page number |
| `per_page` | int | 20 | Items per page |

**Response:**

```json
{
  "items": [
    {
      "bookmark_id": "uuid",
      "chunk_id": "uuid",
      "title": "Stakeholder Analysis Techniques",
      "preview": "Stakeholder analysis is a technique used...",
      "babok_section": "3.2.1",
      "ka_name": "Elicitation and Collaboration",
      "word_count": 450,
      "estimated_read_minutes": 2,
      "question_preview": "Which technique is BEST...",
      "is_read": false,
      "read_at": null,
      "bookmarked_at": "2025-12-24T10:30:00Z"
    }
  ],
  "pagination": {
    "page": 1,
    "per_page": 20,
    "total_items": 12,
    "total_pages": 1
  }
}
```

**PUT `/api/v1/reading/bookmarks/{bookmark_id}/mark-read`**

Marks bookmark as read.

**Response (200 OK):**

```json
{
  "bookmark_id": "uuid",
  "is_read": true,
  "read_at": "2025-12-24T11:00:00Z"
}
```

**Error Responses:**

| Status | Description |
|--------|-------------|
| 401 Unauthorized | Missing or invalid JWT token |
| 403 Forbidden | Bookmark belongs to another user |
| 404 Not Found | `bookmark_id` does not exist |

**DELETE `/api/v1/reading/bookmarks/{bookmark_id}`**

Removes bookmark. Returns 204 No Content.

**Error Responses:**

| Status | Description |
|--------|-------------|
| 401 Unauthorized | Missing or invalid JWT token |
| 403 Forbidden | Bookmark belongs to another user |
| 404 Not Found | `bookmark_id` does not exist |

### Database Schema

```sql
CREATE TABLE reading_bookmarks (
    bookmark_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    enrollment_id UUID NOT NULL REFERENCES enrollments(id) ON DELETE CASCADE,
    chunk_id UUID NOT NULL REFERENCES reading_chunks(id) ON DELETE CASCADE,
    question_id UUID REFERENCES questions(id) ON DELETE SET NULL,
    session_id UUID REFERENCES quiz_sessions(id) ON DELETE SET NULL,
    review_id UUID REFERENCES review_sessions(id) ON DELETE SET NULL,
    is_read BOOLEAN DEFAULT FALSE,
    read_at TIMESTAMP,
    bookmarked_at TIMESTAMP NOT NULL DEFAULT NOW(),
    CONSTRAINT unique_user_chunk_bookmark UNIQUE (user_id, chunk_id)
);

CREATE INDEX idx_reading_bookmarks_user ON reading_bookmarks(user_id);
CREATE INDEX idx_reading_bookmarks_enrollment ON reading_bookmarks(enrollment_id);
CREATE INDEX idx_reading_bookmarks_unread ON reading_bookmarks(user_id, is_read) WHERE is_read = FALSE;
```

**Foreign Key References:**
- `users(id)` - User who created the bookmark
- `enrollments(id)` - Course enrollment context (for multi-course support)
- `reading_chunks(id)` - The reading content being bookmarked
- `questions(id)` - Optional: question that triggered the bookmark context
- `quiz_sessions(id)` - Optional: quiz session context
- `review_sessions(id)` - Optional: review session context (Story 4.9)

### Technical Constraints

- **Idempotency:** Create endpoint must be idempotent (return existing on duplicate)
- **Performance:** Index on (user_id, is_read) for fast unread queries
- **Cascade:** Hard delete on bookmark removal (no soft delete for MVP)
- **Unique:** One bookmark per user-chunk combination
