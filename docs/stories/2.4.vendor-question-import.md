# Story 2.4: Vendor Question Import with Concept Mapping

## Status

Ready for Review

## Story

**As a** content manager,
**I want** to import vendor CBAP questions scoped to a course and map them to concepts,
**so that** questions can update belief states for specific concepts within a course.

## Acceptance Criteria

1. Questions table schema in PostgreSQL **with multi-course support**:
   ```
   - id (UUID, PK)
   - course_id (UUID, FK to courses) - REQUIRED for multi-course
   - question_text (TEXT)
   - options (JSONB) - {A, B, C, D}
   - correct_answer (CHAR 1) - A/B/C/D
   - explanation (TEXT)
   - knowledge_area_id (VARCHAR 50) - references course.knowledge_areas[].id
   - difficulty (FLOAT 0.0-1.0) - IRT difficulty parameter
   - discrimination (FLOAT, default 1.0) - IRT discrimination parameter
   - guess_rate (FLOAT, default 0.25) - P(correct | not mastered)
   - slip_rate (FLOAT, default 0.10) - P(incorrect | mastered)
   - source (VARCHAR) - vendor identifier
   - corpus_reference (VARCHAR 100) - e.g., BABOK section (was babok_reference)
   - times_asked (INT, default 0) - for calibration
   - times_correct (INT, default 0) - for calibration
   - is_active (BOOLEAN, default TRUE)
   - created_at, updated_at
   ```
2. Question-concept junction table `question_concepts`:
   ```
   - question_id (FK)
   - concept_id (FK)
   - relevance (FLOAT 0.0-1.0) - how directly question tests concept
   - PRIMARY KEY (question_id, concept_id)
   ```
3. Python script `/scripts/import_vendor_questions.py`:
   - Read questions from CSV/JSON
   - Validate: Required fields, exactly 4 options, correct_answer is A/B/C/D
   - **Concept mapping:** Use GPT-4 + semantic search to map each question to 1-5 concepts
   - Insert questions and concept mappings
4. Concept mapping process:
   - Generate question embedding
   - Find top-10 most similar concepts by embedding
   - Use GPT-4 to select 1-5 most relevant concepts from candidates
   - Assign relevance scores (1.0 = directly tests, 0.5 = indirectly related)
5. Validation:
   - Each question maps to at least 1 concept
   - Each concept has at least 3 questions (for BKT to work)
   - Concepts with <3 questions flagged for content creation
6. Target: 500-1000 questions imported per course
7. Distribution: Balanced across concepts (not just KAs)
8. Rollback mechanism if import fails
9. Script logs: Questions imported, concept coverage, unmapped questions
10. Human review: Export question-concept mappings for SME validation
11. **Multi-course:** Script looks up course_id from courses table before import
12. **Multi-course:** Validates knowledge_area_id against course's knowledge_areas JSONB

### Knowledge Area ID Mapping

**CBAP Course Knowledge Areas** [Source: database-schema.md#courses seed data]:

| Vendor KA Name                              | knowledge_area_id |
| ------------------------------------------- | ----------------- |
| Business Analysis Planning and Monitoring   | `ba-planning`     |

| Strategy Analysis                           | `strategy`        |
| Requirements Analysis and Design Definition | `radd`            |
| Solution Evaluation                         | `solution-eval`   |

**Mapping Function:**

```python
def map_ka_name_to_id(ka_name: str, course_knowledge_areas: List[dict]) -> str:
    """Map vendor KA name to course knowledge_area_id."""
    # Normalize input
    ka_name_lower = ka_name.lower().strip()

    for ka in course_knowledge_areas:
        if ka["name"].lower() == ka_name_lower:
            return ka["id"]
        if ka.get("short_name", "").lower() == ka_name_lower:
            return ka["id"]

    raise ValueError(f"Unknown KA: {ka_name}")
```

```sql
CREATE TABLE questions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    course_id UUID NOT NULL REFERENCES courses(id) ON DELETE CASCADE,  -- NEW
    question_text TEXT NOT NULL,
    options JSONB NOT NULL,
    correct_answer CHAR(1) NOT NULL,
    explanation TEXT NOT NULL,
    knowledge_area_id VARCHAR(50) NOT NULL,  -- CHANGED from knowledge_area
    difficulty FLOAT NOT NULL DEFAULT 0.5,
    discrimination FLOAT NOT NULL DEFAULT 1.0,
    guess_rate FLOAT NOT NULL DEFAULT 0.25,
    slip_rate FLOAT NOT NULL DEFAULT 0.10,
    times_asked INTEGER NOT NULL DEFAULT 0,
    times_correct INTEGER NOT NULL DEFAULT 0,
    source VARCHAR(50) NOT NULL DEFAULT 'vendor',
    corpus_reference VARCHAR(100),  -- RENAMED from babok_reference
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
    CHECK (correct_answer IN ('A', 'B', 'C', 'D')),
    CHECK (difficulty >= 0.0 AND difficulty <= 1.0),
    CHECK (guess_rate >= 0.0 AND guess_rate <= 1.0),
    CHECK (slip_rate >= 0.0 AND slip_rate <= 1.0)
);

CREATE INDEX idx_questions_course ON questions(course_id);  -- NEW
CREATE INDEX idx_questions_knowledge_area ON questions(course_id, knowledge_area_id);  -- CHANGED
CREATE INDEX idx_questions_difficulty ON questions(difficulty);
CREATE INDEX idx_questions_active ON questions(is_active) WHERE is_active = TRUE;
```

[Source: architecture/database-schema.md#question_concepts]

```sql
CREATE TABLE question_concepts (
    question_id UUID NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
    concept_id UUID NOT NULL REFERENCES concepts(id) ON DELETE CASCADE,
    relevance FLOAT NOT NULL DEFAULT 1.0,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    PRIMARY KEY (question_id, concept_id),
    CHECK (relevance >= 0.0 AND relevance <= 1.0)
);

CREATE INDEX idx_question_concepts_question ON question_concepts(question_id);
CREATE INDEX idx_question_concepts_concept ON question_concepts(concept_id);
```

[Source: architecture/bkt-architecture.md#Question Bank]

Questions are linked to 1-5 concepts via `question_concepts`. When a user answers:

1. BeliefUpdater retrieves `question.concept_ids`
2. Updates belief states for each concept
3. Propagates updates to prerequisites

**Key BKT Parameters:**

- `guess_rate` (P(correct | not mastered)): Default 0.25 for 4-choice MCQ
- `slip_rate` (P(incorrect | mastered)): Default 0.10

| Metric                       | Min | Target  | Max  |
| ---------------------------- | --- | ------- | ---- |
| Total questions              | 500 | 700-800 | 1000 |
| Concepts mapped per question | 1   | 2-3     | 5    |
| Questions per concept (min)  | 3   | 5-10    | -    |
| Concepts with 0 questions    | -   | 0       | 10%  |

### Error Handling

- **Parse Errors:** Log row number, skip invalid questions, continue
- **Validation Errors:** Collect all errors, report at end, reject batch if >10%
- **Embedding API Errors:** Retry with exponential backoff (max 3 retries)
- **GPT-4 API Errors:** Retry with exponential backoff, fallback to semantic-only
- **Database Errors:** Rollback entire transaction, log error, exit with error code
