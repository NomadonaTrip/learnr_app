# Story 5.5: Background Reading Queue Population

## Status

**Approved**

## Story

**As a** system,
**I want to** automatically add relevant reading materials to the user's reading queue as they answer questions,
**so that** users have curated study materials available without interrupting their quiz flow.

## Acceptance Criteria

1. After user answers ANY question (correct or incorrect), trigger async background process to add reading materials
2. For incorrect answers: Add 2-3 high-priority BABOK chunks (semantic search on question concepts + KA)
3. For correct answers on Hard questions: Add 1 medium-priority chunk for reinforcement (optional, configurable)
4. For correct answers on Easy/Medium: Skip reading recommendation (user already understands)
5. Semantic search query composition:
   - Primary: Concept names from `question_concepts` → `concepts` join (e.g., "stakeholder analysis", "requirements elicitation")
   - Secondary: Question text if concepts insufficient
   - Filter: Same KA as question (use `questions.knowledge_area_id`)
6. Celery background task receives parameters and inserts into `reading_queue`:
   - `user_id`, `enrollment_id`, `chunk_id`, `triggered_by_question_id`, `session_id`
   - `triggered_by_concept_id` (primary concept from question)
   - `priority` calculated based on: competency gap in KA (larger gap = higher priority), question difficulty
   - Note: `session_id` passed for context/logging but not stored in reading_queue table
7. Priority calculation logic:
   - High: User competency in KA <60% AND incorrect answer
   - Medium: User competency 60-80% OR correct on hard question
   - Low: User competency >80% AND correct answer (rare, for completeness)
8. Database: Insert into `reading_queue` table with `status = 'unread'`
9. Duplicate prevention: If chunk already in user's queue → update `relevance_score` if higher, don't duplicate
10. Performance: Background process <200ms, doesn't block answer submission response
11. Unit tests: Reading queue population triggered correctly, priority calculation accurate
12. Integration test: Answering questions adds appropriate reading materials to queue

CREATE TABLE reading_queue (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    enrollment_id UUID NOT NULL REFERENCES enrollments(id) ON DELETE CASCADE,

### KA Competency Calculation

To calculate user competency for a Knowledge Area (needed for priority calculation):

```python
async def get_ka_competency(user_id: UUID, knowledge_area_id: str, db: AsyncSession) -> float:
    """
    Calculate average mastery across all concepts in a Knowledge Area.
    Returns value between 0.0 and 1.0.
    """
    query = text("""
        SELECT AVG(bs.alpha / (bs.alpha + bs.beta)) as avg_mastery
        FROM belief_states bs
        JOIN concepts c ON bs.concept_id = c.id
        WHERE bs.user_id = :user_id
          AND c.knowledge_area_id = :ka_id
    """)
    result = await db.execute(query, {"user_id": user_id, "ka_id": knowledge_area_id})
    row = result.fetchone()
    return row.avg_mastery if row and row.avg_mastery else 0.5  # Default to 50% if no data
```

### API Specifications

**Internal Background Call (not exposed as public API):**
The reading queue population is triggered internally via Celery task, not via HTTP endpoint.

**Celery Task Signature:**

```python
from celery import Celery
from src.config import settings

# Celery app configuration (create in src/tasks/__init__.py if not exists)
celery_app = Celery(
    "learnr",
    broker=settings.REDIS_URL,
    backend=settings.REDIS_URL
)

@celery_app.task(bind=True, max_retries=3, default_retry_delay=5)
def add_reading_to_queue(
    self,
    user_id: str,
    enrollment_id: str,
    question_id: str,
    session_id: str,  # For logging/debugging context only
    is_correct: bool,
    difficulty: float
) -> dict:
    """
    Background task to populate reading queue after answer submission.

    Flow:
    1. Get question's knowledge_area_id and concepts
    2. Calculate user's KA competency from belief_states
    3. Determine priority based on competency + correctness
    4. Skip if correct on Easy/Medium question
    5. Search Qdrant for relevant reading chunks
    6. Insert/update reading_queue entries

    Returns:
        {"chunks_added": int, "priority": str, "duration_ms": int}
    """
    import time
    start = time.perf_counter()

    try:
        # Implementation calls ReadingQueueService
        result = await ReadingQueueService.populate_reading_queue(...)
        duration_ms = int((time.perf_counter() - start) * 1000)
        return {"chunks_added": result, "duration_ms": duration_ms}
    except Exception as e:
        self.retry(exc=e, countdown=5 * (2 ** self.request.retries))
```

### Edge Case Handling

| Scenario                        | Handling                                                  |
| ------------------------------- | --------------------------------------------------------- |
| **New user (no belief_states)** | Return default competency 0.5 (50%) - uninformative prior |
| **Question has no concepts**    | Use question text as fallback for semantic search query   |
| **Qdrant returns 0 results**    | Log warning, skip queue population (no error)             |
| **OpenAI API fails**            | Retry with exponential backoff (Celery retry), log error  |
| **Qdrant unreachable**          | Retry with exponential backoff, log error                 |
| **Duplicate chunk in queue**    | Upsert: update priority only if new priority is higher    |
| **Correct on Easy question**    | Skip queue population entirely (AC 4)                     |
