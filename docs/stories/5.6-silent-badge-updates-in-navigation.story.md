# Story 5.6: Silent Badge Updates in Navigation

## Status

**Ready for Done**

## Story

**As a** system,
**I want to** update the reading library badge count silently as new materials are added,
**so that** users are aware of new content without interrupting their quiz flow.

## Acceptance Criteria

1. Navigation bar includes "Reading Library" link with badge count (e.g., "Reading [7]")
2. Badge displays count of `reading_queue` items with `status = 'unread'`
3. Badge updates automatically via WebSocket OR polling (every 5-10 seconds during quiz session)
4. WebSocket implementation (RECOMMENDED):
   - Backend emits `reading_queue_updated` event with new `unread_count` when items added
   - Frontend listens and updates badge count reactively
   - No popup, toast, or notification shown (completely silent)
5. Polling fallback (if WebSocket not implemented in MVP):
   - Frontend polls GET `/api/v1/reading/stats` every 10 seconds during active quiz session
   - Response: `{unread_count: 7, high_priority_count: 3}`
   - Update badge silently
6. Badge styling: Small circular badge (8px border radius), orange/blue color, white text, positioned top-right of "Reading" text
7. Badge appears only when count >0, hidden when count = 0
8. Clicking badge/link navigates to Reading Library page (Story 5.7)
9. Unit tests: Badge count updates correctly when queue items added
10. Integration test: User answering questions sees badge count increment silently

## Dev Notes

### API Specifications

**GET `/api/v1/reading/stats`**

Returns aggregated reading queue statistics for the current user's active enrollment.

**Response Schema:**

```json
{
  "unread_count": 7,
  "high_priority_count": 3
}
```

**Query (SQL equivalent):**

```sql
SELECT
    COUNT(*) FILTER (WHERE status = 'unread') AS unread_count,
    COUNT(*) FILTER (WHERE status = 'unread' AND priority = 'High') AS high_priority_count
FROM reading_queue
WHERE enrollment_id = :enrollment_id;
```

[Source: architecture/database-schema.md#reading_queue]

### Error Handling Strategy

**useReadingStats Hook Error Handling:**

```typescript
// React Query configuration for polling with error handling
const { data, isLoading, isError } = useQuery({
  queryKey: ['readingStats'],
  queryFn: getReadingStats,
  refetchInterval: (query) => {
    // Exponential backoff on error: 10s → 20s → 40s → 60s (max)
    if (query.state.error) {
      const failureCount = query.state.errorUpdateCount;
      return Math.min(10000 * Math.pow(2, failureCount), 60000);
    }
    return 10000; // Normal 10-second interval
  },
  staleTime: 5000, // Consider data stale after 5s
  retry: 2, // Retry twice before showing error state
  retryDelay: (attemptIndex) => Math.min(1000 * 2 ** attemptIndex, 10000),
});
```

**Error Scenarios:**

| Error | Behavior | User Impact |
|-------|----------|-------------|
| Network Error | Keep stale count, backoff polling | Badge shows last known count |
| 401 Unauthorized | Stop polling, auth interceptor redirects | User sent to login |
| 500 Server Error | Backoff polling, keep stale count | Badge shows last known count |
| Timeout | Treat as network error | Badge shows last known count |

**Key Principle:** Never hide the badge on transient errors. Stale data is better than missing UI.
