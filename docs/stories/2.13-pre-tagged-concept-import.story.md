# Story 2.13: Pre-Tagged Concept Import from CSV

## Status

**Ready for Review**

## Story

**As a** content manager,
**I want** to import questions with pre-tagged concepts from CSV files and have them automatically mapped to existing concepts in the database,
**So that** I can efficiently import vendor questions without requiring GPT-4 processing when concept mappings are already known.

## Background

The current `import_vendor_questions.py` script uses GPT-4 + semantic search to map questions to concepts. However, many CSV files already contain a `concept_tags` column with pre-identified concept names. This story adds functionality to:

1. Parse the `concept_tags` column from CSV
2. Match tags to existing concepts using fuzzy matching
3. Optionally create new concepts for unmatched tags
4. Map questions to matched concepts with appropriate relevance scores

This significantly reduces import time and API costs when concepts are pre-identified.

## Story Context

**Existing System Integration:**

- Integrates with: `scripts/import_vendor_questions.py`
- Technology: Python, PostgreSQL, thefuzz (fuzzy matching)
- Follows pattern: Existing `VendorQuestionImporter` class structure
- Touch points: `ConceptRepository`, `QuestionRepository`, CSV parsing

**CSV Format Support:**

Current CSV files use two delimiter styles:

- Comma-separated: `"stakeholder,analysis,planning"`
- Semicolon-separated: `"BA-Planning;Stakeholder-Engagement-Approach;Adaptability;"`

   ```python
   # Parse concept_tags (support both , and ; delimiters)
   tags_raw = row.get("concept_tags", "").strip()
   if tags_raw:
       # Normalize: replace ; with , then split
       tags = [t.strip() for t in tags_raw.replace(";", ",").split(",") if t.strip()]
       question.concept_tags = tags
   ```

3. **Add `ConceptTagMatcher` class:**

   ```python
   class ConceptTagMatcher:
       def __init__(self, concepts: List[Concept], threshold: int = 85):
           self.concepts = concepts
           self.threshold = threshold
           self.concept_by_name = {c.name.lower(): c for c in concepts}

       def match_tag(self, tag: str) -> Optional[Tuple[Concept, float, float]]:
           """Returns (concept, match_score, relevance) or None."""
           # Try exact match first
           normalized = tag.lower().strip()
           if normalized in self.concept_by_name:
               return (self.concept_by_name[normalized], 100, 1.0)

           # Fuzzy match
           best_match = None
           best_score = 0
           for name, concept in self.concept_by_name.items():
               score = fuzz.ratio(normalized, name)
               if score > best_score and score >= self.threshold:
                   best_match = concept
                   best_score = score

           if best_match:
               relevance = 0.8 if best_score < 95 else 0.9
               return (best_match, best_score, relevance)

           return None
   ```

4. **Add `map_questions_from_tags` method to `VendorQuestionImporter`:**

   ```python
   async def map_questions_from_tags(
       self,
       questions: List[QuestionData],
       create_missing: bool = False
   ) -> Dict[int, List[ConceptMapping]]:
       """Map questions to concepts using pre-tagged concept names."""
       matcher = ConceptTagMatcher(self.concepts, self.tag_match_threshold)
       mappings = {}
       unmatched_tags = []

       for question in questions:
           question_mappings = []
           for tag in question.concept_tags:
               result = matcher.match_tag(tag)
               if result:
                   concept, score, relevance = result
                   question_mappings.append(ConceptMapping(
                       concept_id=concept.id,
                       concept_name=concept.name,
                       relevance=relevance,
                       reasoning=f"Matched from CSV tag '{tag}' (score: {score}%)"
                   ))
               else:
                   unmatched_tags.append((question.row_number, tag))

           mappings[question.row_number] = question_mappings

       return mappings
   ```

## Risk and Compatibility

**Primary Risk:** Fuzzy matching may create incorrect mappings for similar concept names

**Mitigation:**

- Default threshold of 85% is conservative
- Export matched mappings to CSV for SME review
- Validate KA consistency between question and matched concept

**Rollback:** Use `--skip-concept-mapping` or existing GPT-4 flow (`--use-csv-tags` not specified)

## Post-Import Considerations

When using `--create-missing-concepts`, be aware of the following system behaviors:

### 1. New Concepts Start as Orphan Nodes (No Prerequisites)

New concepts created from tags will have no prerequisite relationships defined. This means:

- Prerequisite propagation in belief updates won't apply to these concepts
- The concepts appear as "root concepts" in the prerequisite graph

**Follow-up Action:** After import, consider running `scripts/build_prerequisite_graph.py` to infer prerequisite relationships using GPT-4, or manually define relationships for critical concepts.

### 2. Embeddings Required for Semantic Search

New questions (and optionally new concepts) need embeddings uploaded to Qdrant for semantic search functionality:

```bash
# After import, generate and upload embeddings
python scripts/generate_question_embeddings.py --course-slug cbap

# If new concepts were created, also generate concept embeddings
python scripts/generate_concept_embeddings.py --course-slug cbap
```

Without embeddings:

- Semantic question search won't find new questions
- Future GPT-4 concept mapping runs won't consider new concepts

### 3. Reading Chunks Use Semantic Fallback

New concepts won't have reading chunks directly linked via `concept_ids`. However, the `ReadingSearchService` has a semantic search fallback that finds relevant chunks by concept name similarity. This provides acceptable coverage without manual linking.

**Optional Enhancement:** For high-priority concepts, manually link reading chunks or run a semantic linking script.
