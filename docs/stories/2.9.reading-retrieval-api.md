# Story 2.9: Content Retrieval API - Reading by Concept

## Status

## Story

**As a** backend developer,
**I want** an API to retrieve reading chunks for specific concepts within a course,
**so that** users can study content related to their gaps in the enrolled course.

## Acceptance Criteria

1. GET `/v1/courses/{course_slug}/reading` endpoint accepts: **← CHANGED: course-scoped**
   - `concept_ids` (array) - find chunks for these concepts
   - `knowledge_area_id` (optional) - knowledge area filter **← RENAMED from ka**
   - `limit` (default 5)
2. Returns chunks that cover the specified concepts **within the course** **← UPDATED**
3. Ranked by relevance to requested concepts
4. Response includes course_id and concept_ids for each chunk **← UPDATED**
5. Requires authentication
6. Performance: <200ms
7. Fallback: If no chunks for concept, use semantic search with concept name as query **filtered by course_id** **← UPDATED**
8. **Multi-course:** Reading content is scoped to the course in the URL path **← NEW**

### PostgreSQL Array Query Pattern

```python
from sqlalchemy import func, text
from sqlalchemy.dialects.postgresql import ARRAY

async def get_chunks_by_concepts(
    db: AsyncSession,
    course_id: UUID,        # NEW - required
    concept_ids: List[UUID],
    knowledge_area_id: Optional[str] = None,  # RENAMED from ka
    limit: int = 5
) -> List[ReadingChunk]:
    """Get chunks matching requested concepts for a specific course, ranked by relevance."""

    # Convert UUIDs to strings for array literal
    concept_ids_str = [str(cid) for cid in concept_ids]

    # Query with array overlap and relevance scoring
    query = (
        select(
            ReadingChunk,
            func.cardinality(
                func.array_intersect(
                    ReadingChunk.concept_ids,
                    concept_ids_str
                )
            ).label('match_count')
        )
        .where(ReadingChunk.course_id == course_id)  # NEW - always filter by course
        .where(ReadingChunk.concept_ids.overlap(concept_ids_str))
    )

    if knowledge_area_id:  # RENAMED from ka
        query = query.where(ReadingChunk.knowledge_area_id == knowledge_area_id)

    query = query.order_by(text('match_count DESC')).limit(limit)

    result = await db.execute(query)
    return result.all()
```

### Semantic Search Fallback Pattern

```python
from qdrant_client.models import Filter, FieldCondition, MatchValue

async def search_chunks_semantic(
    course_id: UUID,        # NEW - required
    concept_names: List[str],
    qdrant_client: AsyncQdrantClient,
    embedding_service: EmbeddingService,
    limit: int = 5
) -> List[ReadingChunk]:
    """Search chunks using semantic similarity to concept names for a specific course."""

    # Combine concept names into search query
    search_text = " ".join(concept_names)

    # Generate embedding
    embedding = await embedding_service.generate_embedding(search_text)

    # Search Qdrant with course filter
    results = await qdrant_client.search(
        collection_name="reading_chunks",  # CHANGED from "babok_chunks"
        query_vector=embedding,
        query_filter=Filter(               # NEW - filter by course_id
            must=[
                FieldCondition(
                    key="course_id",
                    match=MatchValue(value=str(course_id))
                )
            ]
        ),
        limit=limit
    )

    # Convert to ReadingChunk objects
    chunk_ids = [UUID(r.payload["chunk_id"]) for r in results]
    return await chunk_repo.get_by_ids(chunk_ids)
```

### Refactoring Performed

#### 1. Fixed N+1 Query Problem (Critical Performance Issue)

**Problem:** The original implementation called `get_concept_names()` in a loop for each returned chunk, causing N queries where N = number of chunks × average concepts per chunk.

**Files Modified:**

- **File**: `apps/api/src/repositories/concept_repository.py`
  - **Change**: Added `get_by_ids(concept_ids: List[UUID])` method (lines 88-104)
  - **Why**: Enable batch fetching of concepts in a single database query
  - **How**: Uses SQLAlchemy's `where(Concept.id.in_(concept_ids))` for efficient bulk retrieval
  - **Impact**: Reduces database queries from O(n) to O(1) for concept resolution

- **File**: `apps/api/src/routes/reading.py`
  - **Change 1**: Renamed `get_concept_names()` → `get_concept_names_batch()` (lines 48-65)
    - **Why**: New signature returns `dict[UUID, str]` instead of `List[str]` for O(1) lookups
    - **How**: Uses `get_by_ids()` to fetch all concepts at once
  - **Change 2**: Updated endpoint to batch all concept IDs upfront (lines 169-174)
    - **Why**: Collect all unique concept IDs from request + chunks before fetching
    - **How**: Single batch query fetches all needed concepts, then map is used for lookups
  - **Change 3**: Updated concept name resolution to use pre-fetched map (lines 180-184)
    - **Why**: Eliminate per-chunk database queries
    - **How**: List comprehension uses in-memory map instead of async calls

**Performance Improvement:**
- **Before**: 5 chunks × 3 concepts each = 15 database queries
- **After**: 1 batch query for all unique concept IDs
- **Estimated Improvement**: ~50-100ms reduction in typical request
