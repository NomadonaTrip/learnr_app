## Acceptance Criteria

1. After each diagnostic answer, update beliefs for concepts tested by that question
2. Bayesian update using BKT formula:

   ```python
   def update_belief(belief, is_correct, slip=0.10, guess=0.25):
       p_mastered = belief.alpha / (belief.alpha + belief.beta)

       if is_correct:
           p_correct = (1 - slip) * p_mastered + guess * (1 - p_mastered)
           posterior = (1 - slip) * p_mastered / p_correct
       else:
           p_incorrect = slip * p_mastered + (1 - guess) * (1 - p_mastered)
           posterior = slip * p_mastered / p_incorrect

       belief.alpha += posterior
       belief.beta += (1 - posterior)
       belief.response_count += 1
       return belief
   ```

3. Update all concepts linked to the question (via question_concepts)
4. Persist updates after each answer (not batched)
5. Return updated belief summary in answer response:
   ```json
   {
     "is_recorded": true,
     "concepts_updated": ["uuid1", "uuid2"],
     "diagnostic_progress": 8,
     "diagnostic_total": 15
   }
   ```
6. Logging: "Updated beliefs for {N} concepts after question {id}"
7. Performance: Update completes in <100ms
8. Transaction: All belief updates atomic
9. Unit tests: Bayesian update math, multi-concept updates
10. Integration test: Full diagnostic updates all touched concepts

### BKT Algorithm Details

The Bayesian Knowledge Tracing update follows this mathematical model:

**Variables:**

- `alpha, beta`: Beta distribution parameters representing mastery evidence
- `p_mastered = alpha / (alpha + beta)`: Prior probability of mastery
- `slip`: P(incorrect | mastered) - probability of careless error (default 0.10)
- `guess`: P(correct | not mastered) - probability of lucky guess (default 0.25)

**Update Formula:**

For a **correct** answer:

```python
p_correct = (1 - slip) * p_mastered + guess * (1 - p_mastered)
posterior = (1 - slip) * p_mastered / p_correct
new_alpha = alpha + posterior
new_beta = beta + (1 - posterior)
```

For an **incorrect** answer:

```python
p_incorrect = slip * p_mastered + (1 - guess) * (1 - p_mastered)
posterior = slip * p_mastered / p_incorrect
new_alpha = alpha + posterior
new_beta = beta + (1 - posterior)
```

**Interpretation:**

- `posterior` represents updated probability that user has mastered the concept
- Correct answer increases alpha (mastery evidence)
- Incorrect answer increases beta (non-mastery evidence)
- Initial Beta(1,1) is uninformative prior (uniform distribution)

### Service Architecture

#### BeliefUpdater Service

```python
# apps/api/src/services/belief_updater.py
from typing import Dict, List, Tuple
from uuid import UUID
from datetime import datetime
import structlog

from src.models.belief_state import BeliefState
from src.models.question import Question
from src.repositories.belief_repository import BeliefRepository

logger = structlog.get_logger()

class BeliefUpdater:
    """
    Updates belief states after observing a user response using Bayesian inference.

    This is the core BKT engine for LearnR's adaptive learning.
    """

    def __init__(
        self,
        belief_repository: BeliefRepository,
        default_slip: float = 0.10,
        default_guess: float = 0.25
    ):
        self.belief_repository = belief_repository
        self.default_slip = default_slip
        self.default_guess = default_guess

    async def update_beliefs(
        self,
        user_id: UUID,
        question: Question,
        is_correct: bool
    ) -> List[UUID]:
        """
        Update beliefs for all concepts tested by this question.

        Returns list of concept IDs that were updated.
        """
        start_time = datetime.utcnow()

        # Get concept IDs from question
        concept_ids = [qc.concept_id for qc in question.question_concepts]

        if not concept_ids:
            logger.warning("Question has no linked concepts", question_id=str(question.id))
            return []

        # Fetch current beliefs
        beliefs = await self.belief_repository.get_beliefs_for_concepts(user_id, concept_ids)

        # Compute updates
        updates = []
        for concept_id in concept_ids:
            if concept_id not in beliefs:
                logger.warning("Belief state not found", user_id=str(user_id), concept_id=str(concept_id))
                continue

            belief = beliefs[concept_id]
            slip = question.slip_rate or self.default_slip
            guess = question.guess_rate or self.default_guess

            new_alpha, new_beta = self._bayesian_update(
                belief.alpha, belief.beta, is_correct, slip, guess
            )

            belief.alpha = new_alpha
            belief.beta = new_beta
            belief.response_count += 1
            belief.last_response_at = datetime.utcnow()
            updates.append(belief)

        # Persist all updates atomically
        await self.belief_repository.bulk_update(updates)

        duration_ms = (datetime.utcnow() - start_time).total_seconds() * 1000

        logger.info(
            "Updated beliefs for concepts after question",
            user_id=str(user_id),
            question_id=str(question.id),
            concepts_updated=len(updates),
            duration_ms=round(duration_ms, 2)
        )

        if duration_ms > 100:
            logger.warning("Slow belief update", duration_ms=round(duration_ms, 2))

        return [b.concept_id for b in updates]

    def _bayesian_update(
        self,
        alpha: float,
        beta: float,
        is_correct: bool,
        slip: float,
        guess: float
    ) -> Tuple[float, float]:
        """
        Core Bayesian update for Beta distribution parameters.

        Args:
            alpha: Current alpha parameter
            beta: Current beta parameter
            is_correct: Whether the answer was correct
            slip: P(incorrect | mastered)
            guess: P(correct | not mastered)

        Returns:
            Tuple of (new_alpha, new_beta)
        """
        p_mastered = alpha / (alpha + beta)

        if is_correct:
            p_correct = (1 - slip) * p_mastered + guess * (1 - p_mastered)
            posterior = (1 - slip) * p_mastered / p_correct
        else:
            p_incorrect = slip * p_mastered + (1 - guess) * (1 - p_mastered)
            posterior = slip * p_mastered / p_incorrect

        new_alpha = alpha + posterior
        new_beta = beta + (1 - posterior)

        return new_alpha, new_beta
```

### Repository Pattern

#### BeliefRepository

```python
# apps/api/src/repositories/belief_repository.py
from typing import Dict, List
from uuid import UUID
from sqlalchemy import select, and_
from sqlalchemy.ext.asyncio import AsyncSession

from src.models.belief_state import BeliefState

class BeliefRepository:
    """Repository for belief state database operations."""

    def __init__(self, db: AsyncSession):
        self.db = db

    async def get_beliefs_for_concepts(
        self,
        user_id: UUID,
        concept_ids: List[UUID]
    ) -> Dict[UUID, BeliefState]:
        """
        Get belief states for specific concepts with row-level locking.
        """
        result = await self.db.execute(
            select(BeliefState)
            .where(and_(
                BeliefState.user_id == user_id,
                BeliefState.concept_id.in_(concept_ids)
            ))
            .with_for_update()  # Row-level lock for concurrent safety
        )
        beliefs = result.scalars().all()
        return {b.concept_id: b for b in beliefs}

    async def bulk_update(self, updates: List[BeliefState]) -> None:
        """
        Bulk update belief states atomically.
        """
        for belief in updates:
            self.db.add(belief)
        await self.db.flush()
```

### Concurrency Considerations

**Row-Level Locking:**

The `get_beliefs_for_concepts` method uses `SELECT ... FOR UPDATE` to prevent concurrent modification of belief states. This ensures:

- Two simultaneous answer submissions don't corrupt belief data
- Atomic updates within a transaction

**Transaction Isolation:**

All belief updates occur within a single database transaction. If any update fails, all changes are rolled back.

[Source: docs/architecture/backend-architecture.md#belief-state-update-locking]
